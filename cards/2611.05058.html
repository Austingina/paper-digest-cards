深读｜Do Agentic Policies Need to Look at Every Step? Geometric Abstraction for Reasoning and Action

📐 原版模型结构图详解🤖 向千问提问本篇论文原文 ↗

问题

  • 多模态语言模型可以直接读取机器人图像并规划动作，但闭环操作若每一步都重新解释原始视觉，会重复消耗多模态 token 和推理时间；模型对度量距离、表面朝向及结构关系的视觉估计也容易波动。
  • 现有接口存在两端缺口：原始图像信息丰富但推理开销高，常规感知 API 的中心点或包围盒又过于粗糙，难以表达“底面与顶面对齐”“是否稳定支撑”等操作关系。
  • 论文在仿真桌面操作中研究两种设定：跨重置 rollout 修订可执行程序的离线策略合成，以及场景不重置、失败后继续恢复的在线闭环执行；前者在训练结束后冻结程序，后者不训练策略权重，而是在 episode 内持续调用语言模型选择已有技能。
  • 作者的目标是验证：显式、可局部更新的三维几何状态能否替代大部分逐步看图，在提高多步任务完成率的同时减少多模态查询与等待开销。

方法

  • 视觉观测（Visual Observation）：系统接收当前场景图像/深度观测 $o_t=(I_t,D_t)$，通过局部视觉落地将像素特征投影为度量三维几何 $\mathcal{G}_t=\{(\mathbf{x}_i,\mathbf{f}_i)\}$；其中 $\mathbf{x}_i\in\mathbb{R}^3$ 表示物体、区域或关键点在当前坐标系中的位置。
  • 几何抽象（Geometric Abstraction）：度量几何被压缩为符号引用 $s_i$ 与紧凑文本检查点 $c_t$，形成语言模型可读取的接口 $\mathcal{A}_t=\{(s_i,r_i,c_t)\}$。关系 $r_i$ 描述“目标、支撑面、抓取点”等稳定几何角色，避免把连续坐标直接写入推理过程。
  • 文本与符号推理（Reasoning in Text and Symbols）：策略 $\pi$ 基于任务指令 $q$、检查点 $c_t$ 和符号集合 $\mathcal{A}_t$ 生成高层动作序列 $a_{1:H}^{\mathrm{sym}}=\pi(q,c_t,\mathcal{A}_t)$；推理围绕角色及空间关系展开，因此可跨视角、场景布局和执行时刻复用。
  • 动作执行与度量重绑定（Action / Metric Rebinding）：执行阶段将符号动作中的稳定角色重新绑定到当前几何 $\mathcal{G}_t$，得到实时位姿或控制目标 $\mathbf{g}_t\in SE(3)$，再由低层控制器输出机器人动作 $u_t$；新观测持续更新坐标值，构成“观测—抽象—推理—执行”的闭环。

Geometric abstraction between observation, reasoning, and action. Visual observations are grounded locally into metric 3D geometry and exposed to the language model through symbolic references and compact textual checkpoints. Policies reason in text and symbols over stable geometric roles whose metric values are rebound to the current scene during execution.
  • 整体 pipeline 为：侧视与腕部 RGB-D、相机标定和机器人本体状态 → 本地三维几何接地 → 类型化符号引用与文本检查点 → 语言模型组合几何操作或选择技能 → 执行动作 → 用新观测重新接地。
  • 几何状态不只表示物体中心，还包括顶点、边和带朝向的表面；每个元素记录时间戳及 observed、由初始化形状先验推断或因遮挡而不可用的证据状态。形状信息可以保留，但物体移动后的位姿必须由当前观测重新估计，不能沿用旧状态或用指令动作推算。
  • 策略通过 red.bottom_face、blue.top_face 一类“物体—几何角色”引用访问场景。引用在执行时绑定到当前度量值，因此程序可以保留“对齐哪些部件”的结构，而不硬编码特定坐标。
  • 接口提供关系查询、表面对齐、支撑检查和 checkpoint 等算子。以放置为例，对齐算子依据两个配合面的中心和法向计算刚体变换；若几何证据不足则返回未知，而不是把陈旧估计当作事实。支撑为真也只表示几何候选，不保证真实接触或稳定。
  • 每次动作后，文本检查点报告相关坐标、证据状态以及当前位置到目标的度量残差；遮挡导致当前位姿不可恢复时，目标仍被保留，但残差明确标为不可用。图像没有被彻底禁用，几何状态无法解释失败或需要新场景语义时仍可按需调用。
  • 与 Pixel Reasoning 对照相比，任务说明、传感器、执行器和初始技能不变，也都不能读取仿真器真值；改变的是 Geometric Abstraction 额外获得本地接地的部件引用、几何算子和文本反馈，而 Pixel Reasoning 需要在生成程序中自行实现视觉感知或在线反复请求图像。

实验与结果

  • 单策略获取中，第一次修订 R1 后，Geometric Abstraction 在 Bridge+cylinder 上达到 45.2% 测试成功率，Pixel Reasoning 为 21.2%；Three-cube stacking 分别为 57.2% 和 17.2%。
  • 到 R2，几何接口在上述两项任务上分别达到 63.4% 和 72.2%，已经超过 Pixel Reasoning 的最终 R3 成绩 56.0% 和 70.8%；累计 token 分别为 67.3k 对 125.7k、64.7k 对 138.1k，约以一半 token 达到更高成功率。R3 时几何接口最终为 65.4% 和 81.4%，并呈现更低的链间方差。
  • Ring-on-peg 的策略获取更依赖精细部件对齐：两种条件到 R2 的保留策略测试成功率均为 0.0%，R3 时 Geometric Abstraction 达到 38.0%，Pixel Reasoning 仍为 0.0%。作者同时强调，这一差异混合了程序合成与执行期本地几何接地的作用，不能单独归因于文本格式或语言模型推理速度。
  • 连续在线执行中，Geometric Abstraction 在 Bridge-tower 完成 28/50（56%），Pixel Reasoning 为 12/50（24%）；Tower relocation 为 42/50（84%）对 15/50（30%）。这些 episode 失败后不重置，模型等待、物理执行和恢复共同占用 200 秒预算。
  • Ring-on-peg 在线任务中，两者完成率接近，分别为 50/50 与 49/50，但几何接口平均用时从 115.8 秒降至 77.2 秒，快 33.3%，并在 50 对配对布局中的 45 对更早完成。
  • Ring-on-peg 的模型请求时间从 90.0 秒降至 45.6 秒（下降 49.4%），记录 token 从 214.5k 降至 101.3k（下降 52.8%），平均完成请求数从 11.88 降至 6.90，附带图像数从 10.94 降至 2.72。Tower relocation 的模型时间和 token 分别下降 60.5% 与 52.5%；Bridge-tower 则以少 6.7% 的模型时间、但多 15.1% 的 token，将完成率提高到原来的两倍以上，说明收益不只是压缩提示词。

局限与可以继续做的

  • 证据仅来自规则几何物体上的仿真桌面操作；真实 RGB-D 噪声、严重遮挡、相机标定漂移和抓取接触误差下是否仍能可靠重绑定，论文尚未验证。
  • 本地接地采用轻量 CPU 几何估计器，并依赖初始化阶段获得的物体形状信息；关节物体、形变物体以及学习式三维感知均不在当前实验范围内。
  • 几何关系只提供候选条件：表面对齐或支撑检查不能证明真实接触、摩擦稳定性和任务语义正确。该限制对于“已经抓起物体，但未送到正确目标”尤其关键。
  • 对照实验改变了整套可用接口，策略合成收益又包含执行期几何接地效果，因此尚未分别量化类型化部件、证据标签、度量残差和文本压缩各自的贡献；正文提供的内容也未报告移除或扰动这些字段的系统消融。
  • 可以继续做的实验包括：在真机上注入深度噪声与外参漂移；随机遮挡后检查系统是否拒绝陈旧位姿；把 checkpoint 的目标、法向或残差置零、反向和跨物体交换；在物体×目标×场景留出组合上比较纯图像、仅符号、符号加按需图像三种条件，从而区分表示复用与熟悉关联记忆。
实验设置
  • 平台：仿真 SO-100 机械臂；标定的侧视和腕部 RGB-D 相机；输入还包括机器人本体状态。
  • 访问约束：不向任何条件开放仿真器物体位姿或私有评测状态；Pixel Reasoning 与 Geometric Abstraction 使用匹配的任务说明、传感器、执行器和初始技能。
  • 策略合成模型：gpt-6-astra，high reasoning effort；每个任务运行 5 条配对训练链，使用独立的持久语言模型上下文。
  • 策略合成任务：Bridge+cylinder、Three-cube stacking、Ring-on-peg；物体位姿和颜色随机化。
  • 策略合成协议：5 个共享训练布局；从 observation-only scaffold R0 开始，产生 R1–R3 三次程序修订；每一版在全部 5 个训练布局上执行，rollout 之间重置，rollout 内不调用语言模型。
  • 候选保留规则：必须在所有此前已解决的训练布局上继续成功，并至少新增解决一个布局，否则保留 incumbent；训练结束后冻结程序，每个保留版本在每项任务的 100 个共享留出布局上评测。
  • 策略合成成功判据：完成目标排列、释放物体并保持稳定；图中成功率为 5 条训练链所保留策略的平均留出测试成功率。
  • 在线模型：gpt-6-astra，medium reasoning effort；共享桥接/堆叠技能、传感器驱动的 ring grasp-and-lift 前缀及放置例程，两种条件都可按需请求图像和深度采样。
  • 在线任务：Bridge-tower、Ring-on-peg、Tower relocation；每项 50 个配对布局，共 300 个 episode。
  • 在线协议：单个连续场景最多运行 200 秒，动作失败后不重置；物理仿真在模型等待期间继续推进，超时在 capped completion time 中按 200 秒计。
  • 成本统计注明：Ring-on-peg Pixel Reasoning 的部分 token 统计排除了两次被中断请求中无法获知的用量。
AI导读和推荐理由
  • 推荐这篇的核心原因不是它提出了新的端到端机器人策略，而是它把“语言模型是否必须每步看图”转化为一个可测的接口问题：哪些结构可长期复用，哪些度量状态必须由当前观测重新绑定。
  • 论文同时报告闭环完成率、恢复过程、模型等待时间、token 与图像附件数量，能够避免仅用离线预测精度或提示词长度论证表示有效。

与本项目关系

  • 论文的类型化部件引用和度量残差，与 Austin 项目的 G / A-F 都属于“把高维视觉压成策略可读的几何条件”。区别在于，本文主要描述当前物体部件、对齐关系和目标误差；A/F 更明确地区分“接近哪个交互区域”与“物体应如何变化”，并把接触和时序交给学习到的执行策略。
  • “符号任务结构复用、度量值随当前 RGB-D 重绑定”直接对应本项目对闭环条件遵循的关注：策略不应只在开始时读取一次目标，也不能把期望动作结果当作实际状态。不过论文没有做 G 式的置零、反向或交换消融，因此尚不能证明语言模型使用的是几何语义，而不是稳定的符号名称或任务模板。
  • 与 Austin 当前路线的联系主要停留在表示和闭环接口层。论文不使用 OpenPI、π0 或 π0.5，也没有评测物体×目标×场景的交叉覆盖与未见组合；其执行层是程序和已有技能编排，不能直接说明预训练 VLA 会如何吸收 G。
  • 对“抓到了但未送到正确目标”和“是否持续跟随目标”，论文的动作后 checkpoint 与残差重算提供了有用机制；但它没有单独分析错误目标关联、长时目标跟随、放置数据覆盖或失败恢复数据是否充分。

启发

  • 在 OpenPI 执行器外增加与本文类似的局部 monitor：每个 action chunk 后，从视觉重新估计 A 对应区域、物体实际运动及其相对 F 的残差，并把 observed / inferred / unavailable 与时间戳一并记录；不可观测时禁止沿用旧残差。
  • 将“条件遵循”评测扩展为配对闭环实验：在完全相同初始图像下分别输入原始 G、置零 G、反向 G、跨目标交换 G，比较物体轨迹与目标残差是否按几何条件系统变化，而不只比较最终成功率。
  • 增加“符号结构固定、度量值重绑定”的组合测试：训练覆盖部分物体×目标×场景组合，测试时保留同一 A/F 结构但更换坐标、对象和目标；另设符号名称随机化，排查策略是否把字段当作任务 ID。
  • 对放置与恢复分别记录抓取成功、目标选择正确、运输中持续跟随、释放位置误差、释放后稳定性和恢复次数，避免最终成功率掩盖“会抓但不会送”或“放置后失稳”。
  • 做三路执行对照：OpenPI 仅看原始视觉、OpenPI 接收 A/F、OpenPI 接收 A/F 加动作后度量 checkpoint；同时统计成功率、action chunk 数、视觉刷新次数和恢复时间，以判断收益来自意图表示还是闭环状态更新。

一句话总结

独立研究者 Yihang Liu、Georgia Tech 的 Yiming Chen 与香港科技大学的 Mingzhe Zheng 用可重绑定的三维部件符号和文本残差替代大部分逐步看图，使在线 Tower relocation 完成率由 30% 提至 84%，并将该任务的模型时间与 token 分别降低 60.5% 和 52.5%。
