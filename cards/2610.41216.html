问题

  • 基于 VLM 的机器人智能体不仅依赖规划器，还高度依赖其外围 harness：工具接口、感知与运动执行、反馈、任务记忆和故障恢复。现有研究通常分别优化 harness 或蒸馏小模型，尚缺少“先演化系统、再把系统收益迁移到小模型”的系统验证。
  • 大型规划器虽然具备较强推理与恢复能力，但在线推理计算开销高；直接训练紧凑型端到端 VLA，又往往依赖大规模同分布机器人示范，并可能在扰动和失败恢复场景中退化。
  • 本文采用闭环工具调用式操控：规划器根据图像、指令、工具反馈和夹爪状态逐步决策，不直接输出底层关节动作；教师权重在 harness 演化期间保持冻结，最终 harness 也在蒸馏和部署阶段冻结。
  • 作者目标是把大教师在自演化 harness 中形成的推理、工具调用和故障恢复能力迁移给 0.8B–4B 小模型，在尽量保持成功率的同时降低部署推理计算成本。

方法

  • 阶段一—Harness Evolution：人类预先设定规则、预算与统计门限；冻结教师规划器 $\pi_T$ 经工具、反馈、记忆和恢复模块组成的执行框架 $H$ 产生轨迹。前沿 LLM 智能体 Master 读取轨迹并提出 $H\!\rightarrow\!H'$ 的编辑，全程不更新模型权重。
  • 配对筛选—Statistical Gate：候选 $H'$ 与当前 $H$ 在相同 selection seeds 上进行配对 A/B 测试；仅当严格成功率 $S$ 通过预注册统计检验时才接受修改，循环迭代得到最终框架 $H^*$，避免以偶然收益驱动演化。
  • 阶段二—Trajectory Distillation：冻结 $H^*$，收集教师在其中执行的完整轨迹 $\tau=\{o_t,\text{reasoning}_t,a_t,r_t\}_{t=1}^{T}$，其中每轮仅生成一个工具调用 $a_t$；数据保留推理、失败反馈与 recovery branches，并与离线真实机器人监督混合，训练 $0.8$B–$4$B 的学生 $\pi_S$。
  • 部署与评测—Student-in-the-Loop：以 $\pi_S$ 替换 $\pi_T$，但继续复用同一 $H^*$；规划器决定“做什么”，框架负责感知、抓放几何、无碰规划、闭环纠错及 done 谓词核验。评测覆盖三个训练域、三个未见基准及 SO-ARM101 的三项闭环真机任务。

Overview of \ours. Stage~1: humans specify the rules and budget in advance. A master of frontier LLM agents reads trajectories of the frozen teacher acting through the harness (tools, feedback, memory, recovery) and proposes harness edits, which are accepted only if a paired A/B test on selection seeds passes a pre-registered statistical gate; model weights never change. Stage~2: after evolution ends, we freeze $H^*$ and collect teacher trajectories, including reasoning and recovery branches. These are mixed with offline real-robot supervision to train tiny students (0.8B--4B), which replace the teacher in the same harness. Evaluation covers three training domains and three unseen benchmarks, plus three closed-loop real-robot tasks on an SO-ARM101 arm.
  • TinyAstral 是两阶段 pipeline：先让冻结教师通过可统计检验的递归自改进演化 harness，再冻结最终 harness，采集教师的推理、工具调用与恢复轨迹，训练小型学生替换同一 harness 中的教师。
  • 智能体每轮接收相机图像、任务指令、近期工具结果和夹爪状态，输出一段 reasoning 及且仅一个工具调用；harness 负责 SAM 3 分割、深度点云、抓放几何、无碰撞运动规划和闭环修正，规划器负责对象、顺序、空间关系及终止判断。
  • RSI 阶段只有 harness 被修改。由多个 frontier LLM agent 组成的 master 阅读教师轨迹、把失败归入十类问题，并提出新工具、感知修复、更真实的工具返回、恢复逻辑或局部任务记忆修改；master 本身不直接控制机器人。
  • 候选修改在相同任务—随机种子对上与当前版本做配对 A/B 测试，只有通过预注册统计门限且未在其他任务上产生不可接受回退时才被接纳；新组件必须通过显式触发器留下日志标记，未触发时还要经代码审计确认行为与父版本逐步一致。
  • 数据蒸馏保留教师的 `` 推理和下一次工具调用，并从成功轨迹分叉注入抓取滑落、抓取失败、推动不足或物体位移等扰动；只有扰动确实发生、回放结果一致且教师最终重新达到严格成功的恢复分支才进入训练集。
  • 相对端到端 VLA，TinyAstral 没有把视觉观测直接映射成连续底层动作，也没有在 RSI 中更新教师权重；它训练的是处于固定工具接口之上的小型规划器，并让学生部署在与教师相同的冻结 harness 中。

实验与结果

  • 在同一组 500 个 RoboTwin episode 上，冻结教师 Qwen3.8-Flash-Next 随 harness 从 \(H_1\) 演化到 \(H^*\)，严格成功率由 33.4% 提升至 63.6%，绝对增加 30.2 个百分点。
  • 四个 harness 快照对应的 TinyAstral-4B 学生分别达到 36.2%、49.8%、60.0% 和 62.8%；最终学生仅比同 harness 下的教师 63.6% 低 0.8 个百分点，支持 harness 改进可以经轨迹蒸馏迁移到紧凑模型。
  • 演化后的 harness 对未重新训练的其他规划器也有效：DeepSeek-V4.1-Flash 从 32.8% 提升至 63.4%，未训练的 Qwen3.5-4B 初始化从 14.6% 提升至 41.2%，对应增益分别为 30.6 和 26.6 个百分点。
  • 在相同 episode 的对照中，最终 4B 学生在 Guava 达到 93.6%，对照系统为 78.9%；在 LIBERO-PRO 达到 78.3%，两个对照结果为 57.3% 和 53.0%。原文说明这些对照包括开放 4B agent、27B SenseNova-RoboRSI，以及把本文教师放入三个竞争 harness 的组合，但当前节选未给出每个数字与具体系统的一一对应表。
  • 推理文本具有明显作用：在保持训练样本不变、只清空 reasoning 的消融中，LIBERO-PRO、SimplerEnv Google VM 和 VLABench 成功率分别下降 19.3、11.2 和 10.0 个百分点。
  • 作者报告 4B 学生在三个未参与 RSI 或训练的基准上接近同 harness 的 552B 规划器，并在实测部署 episode 中只使用约为教师五分之一的加速器时间；当前原文节选未提供这些结果的逐基准数值、置信区间或加速器时间绝对值。

局限与可以继续做的

  • 关键 harness 演化发生在 RoboTwin，且 RoboTwin 独享每任务一条可在开发种子上完善的终态记忆；尽管评测种子隔离，仍需区分通用 harness 改进与基准特定任务记忆带来的收益。
  • 论文主要研究基于离散工具调用的高层规划器，不直接输出关节角或连续动作，因此结果不能直接外推到 π0/π0.5 一类端到端连续控制 VLA，也没有证明同样的 RSI 方法能优化其动作策略。
  • 训练数据来自教师成功轨迹并经严格成功过滤，能够提高监督质量，但可能削弱学生对教师未能恢复的长尾失败模式的覆盖；恢复分支也只包含预定义扰动类型。
  • 当前提供的正文在第 4.2 节中途截断，附录和完整对比表不可见，因此 0.8B、2B 学生的完整逐基准结果、统计门限细节、硬件型号、训练超参数以及与各基线数字的精确映射无法从节选核对。
  • 可以继续做的实验包括：在完全取消 RoboTwin 任务记忆后重新比较四个 harness 快照；加入未预设的感知漂移、遮挡和运动规划失败；报告不同模型规模下的成功率—延迟—显存 Pareto 曲线；并将同一高层学生接入 OpenPI 或其他 VLA 执行器，检验 harness 的恢复逻辑能否迁移到连续动作后端。
实验设置
  • 教师规划器：开放权重 Qwen3.8-Flash-Next；RSI 全程冻结其模型权重。
  • 学生模型：Qwen3.5 系列 0.8B、2B 和 4B；正文明确说明 4B 版本微调全部语言模型参数，共训练 2 个 epoch，部署时以 bf16 在单个加速器上运行。
  • 最终训练集：83,753 个决策样本，约一半来自仿真；训练域包括全部 50 个 RoboTwin 任务、7 个已见 Guava 任务和 LIBERO-90。
  • RoboTwin 恢复数据：3,471 个分支样本与 13,857 个主 episode 样本，恢复分支被下采样至 RoboTwin 样本的 20%；物体位移扰动幅度为 6–10 cm。
  • 真实机器人离线监督来自 AgiBot World，以及 Open X-Embodiment 中的 Fractal、BridgeData V2、DROID 和 Berkeley UR5；包含状态与失败判断 27,918 条、子目标规划 4,187 条、下一工具调用 9,771 条。
  • RoboTwin 2.0：50 个任务，每任务 10 个评测种子，共 500 个 episode；工具调用预算为 30 次。训练、选择和评测种子使用互不相交的范围，评测种子编号不小于 100,000。
  • Guava：15 个任务，每任务 30 个官方种子，共 450 个 episode；其中 7 个任务参与训练、8 个任务未见，评测种子与训练种子不重合。
  • LIBERO-PRO：300 个 episode，覆盖三个 LIBERO suite、原始条件及四种扰动，每种设置使用 2 个种子；训练数据只来自 LIBERO-90。
  • 零样本基准：SimplerEnv Visual Matching 共 960 个 episode，覆盖 Google Robot 和 WidowX；VLABench 使用官方列表前 500 个 episode、覆盖五个 track；EB-Manipulation 共 228 个 episode。三者均未参与 RSI 或训练。
  • 主指标为严格成功率：只有智能体主动调用 done，且最终状态满足基准成功谓词才计成功；未确定结果按失败处理。VLABench 和 EB-Manipulation 使用各自官方成功定义。
  • 智能体的 done 谓词由相机和夹爪传感器检查；检查失败后会向模型返回测量结果，连续两次拒绝后，下一次 done 不再检查并终止 episode。模型也可调用 give_up，或因耗尽调用预算而终止。
  • 教师采集主轨迹时默认温度为 0；失败训练种子最多以温度 0.7 重试两次，且提示保持不变。评测时，同一 harness 内所有规划器均以温度 0 解码。
  • harness 快照为 \(H_1\)、\(H_7\)、\(H_{16}\) 和 \(H^*\)；最终整合阶段 7 个候选中有 3 个被接纳。正文还说明完整主线从 \(H_0\) 经 \(H_{16}\) 到 \(H^*\)，共涉及 296 个候选 capability。
  • 真机部分使用 SO-ARM101 机械臂并包含三个闭环任务；当前节选未披露相机型号、episode 数、具体任务定义和硬件配置。
AI导读和推荐理由
  • 推荐这篇论文的核心原因不是它提出了另一种端到端 VLA，而是它把“模型能力”拆成规划器与 harness 两部分，并用四个连续快照证明：外围系统的改进可以较稳定地蒸馏到小型规划器，而非只对原始大模型有效。
  • 对 π 系列研究者而言，它提供了一个互补视角：除了扩大机器人数据和改进动作生成模型，还可以对执行接口、反馈真实性、失败检测、任务记忆与恢复逻辑进行可审计、带统计门限的闭环优化。

与π系列的关系

  • TinyAstral 与 π0、π0.5 同属通用机器人操控方向，但技术接口不同：π 系列端到端 VLA 从观测生成机器人动作，TinyAstral 则让 VLM 规划器逐轮调用感知、抓放、验证和恢复工具，底层几何与运动规划由 harness 执行。
  • 论文相关工作提到 π0 和 π0.5，但当前原文没有显示 TinyAstral 继承它们的权重、数据、动作表示或训练框架，也没有给出与 π0、π0-FAST、π0.5 或 OpenPI 的直接实验对比。
  • TinyAstral 在 RSI 阶段不修改教师模型，在部署阶段也不改 harness，只训练替换教师的高层学生；因此其 4B 参数规模不能与端到端 VLA 的参数量直接等同，成功率也不能跨不同动作接口和评测协议直接横比。
  • 两条路线具有潜在互补性：可把 π0/π0.5 或 OpenPI 策略视作高层工具调用下的连续动作执行器，让 TinyAstral 式 harness 负责目标选择、状态核验、恢复调度和终止判断，但论文尚未验证这一组合。

对Austin研究的启发

  • 在 OpenPI 执行器外增加结构化返回接口：每次技能执行后显式报告目标对象、动作完成度、失败类别、夹爪状态和可恢复性，避免上层规划器只能从下一帧图像隐式猜测执行结果。
  • 对引导场 \(G\) 的条件遵循建立类似 paired gate 的评测：固定相同初始状态和随机种子，对候选引导或恢复模块做配对测试，同时检查目标任务增益与非目标任务回退，而不是只比较独立 episode 的平均成功率。
  • 保存多个 harness 快照，并在每个快照上用同一学生初始化、相同数据预算和训练 recipe 独立蒸馏；若学生性能随 harness 单调提升，才能区分“教师更强”与“数据量更多”。
  • 为闭环评测加入严格终止指标：区分曾经完成、最终状态仍完成、模型主动正确结束三种情况，并记录错误 done、重复操作、恢复次数和预算耗尽，避免成功状态被后续动作破坏后仍计为成功。
  • 在轨迹采集中主动注入 OpenPI 常见执行故障，例如抓取滑落、末端位姿偏差、遮挡、动作 chunk 中断和安全过滤拒绝；只保留故障确实发生且最终恢复成功的分支，同时另建无法恢复的诊断集，避免训练集只覆盖“容易恢复”的失败。
  • 监控每个恢复组件的触发日志，并验证未触发时系统与父版本行为一致；这能把 harness 改动的收益归因到具体模块，也便于发现隐式改变正常轨迹的回归。

一句话总结

TinyAstral 由华为技术有限公司、华为诺亚方舟实验室及独立研究者的作者团队提出，通过先演化冻结教师的 harness、再蒸馏到同一 harness 中的紧凑规划器，将 RoboTwin 教师严格成功率从 33.4% 提升到 63.6%，并使最终 4B 学生达到 62.8%。
