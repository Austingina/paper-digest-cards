问题

  • 基础模型擅长任务分解、代码生成和成功判定，但不适合直接承担细粒度控制：论文报告，ASPIRE 的修复循环在每个 LIBERO 任务上中位耗时 43 分钟，Codex + GPT-6 为 60 个 LIBERO-Pro 任务生成程序时消耗了 8900 万输入 token。
  • 快速 VLA、全身控制器和代码策略能以数 Hz 至数十 Hz 闭环执行，却可能在分布偏移下失效；论文指出，在标准 LIBERO 上超过 90% 的 VLA 面对 LIBERO-Pro 扰动测试集时会明显退化。
  • 现有“大脑—小脑”组合存在两类具体故障：让智能体同步调用快速策略会阻塞控制；仅在策略报错时调用智能体，又会反复触发同一错误并漏掉无异常的静默失败。论文的一组 LIBERO-Pro 测试中，异常触发路由在 590 个 episode 中只升级 6 次，而实际有 166 次失败。
  • 本文研究跨仿真与真机的闭环运行时，System 0 策略可为冻结代码、VLA 或全身控制器；目标是在不让运行中策略等待慢速“大脑”的前提下，统一调度异构策略、提高成功率与控制效率，并使恢复开销受单一预算约束。

方法

  • 单策略基线（Fix/Evo）：输入任务指令 $g$ 与初始观测 $I_0$，执行程序策略 $\pi_k$ 产生动作序列 $a_t=\pi_k(I_t,g)$。Fix 可能在任务未完成时终止；Evo 虽可合成更强策略，但离线搜索与生成成本更高。
  • 视觉判定门（Visual Judge）：每轮将初始帧 $I_0$、当前帧 $I_t$ 和指令 $g$ 联合输入视觉判定器，输出完成判断 $d_t=J(I_0,I_t,g)\in\{\mathrm{done},\mathrm{not\ done}\}$；若为 not done，则继续路由而非读取评测成功信号。
  • 程序执行与路由（Program Executor/Router）：执行器运行离线生成并冻结的程序集合 $\Pi=\{\pi_1,\ldots,\pi_K\}$；路由器依据当前状态 $s_t$ 和 route memory 中的路由表选择下一策略 $\pi_{k_{t+1}}=R(s_t,g,M)$，并按 first/other/first escalation ladder 逐级切换。
  • 共享预算与停止评测：所有策略调用共同消耗统一预算 $B$，满足 $\sum_k c_k\le B$；当 $d_t=\mathrm{done}$ 或预算耗尽时停止。真实成功标记 $y$ 仅在停止后读取一次，只用于最终评估，不参与判定、路由或策略执行。

\textbf{Overview of \rea{} with programmatic policies.} Top left: a single policy may end with the task unfinished (Fix), and a stronger policy is expensive to synthesise (Evo). Top right: the \syst{} visual judge compares the episode-initial and current frames with the instruction, answers not done, and the router dispatches the next policy from the current state. Bottom: \sysz{} runs frozen programs generated offline; \syso{} selects them with a route table (route memory) and a first/other/first escalation ladder; \syst{} is the visual judge gate. All runs share one budget; success is read once, after stopping, for evaluation only.
  • REA 将控制分为三级：System 2 离线生成候选策略、在线提供建议或视觉判定；System 1 只负责策略选择、完成判定与恢复调度，不直接输出动作；System 0 以原生频率闭环执行 VLA、代码策略或全身控制器，并在策略或动作段边界归还控制权。
  • 路由记忆在开发集上记录每个“任务—策略”组合的成功率与平均步数；测试时优先选择成功率最高者，平局时选择步数更少者，从而把 System 2 移出初始 dispatch 路径。遇到选择困境时，运行时仍可调用 System 2。
  • 边界触发 judge gate 在每次策略返回时比较初始帧、当前帧和任务指令，输出 done 或 not_done：前者立即停止，避免重复执行破坏已经完成的任务；后者沿恢复阶梯升级，因此能够处理不抛异常的静默失败。
  • 升级阶梯从当前机器人状态继续执行其他候选策略；所有策略运行和脑调用共享同一剩余步数与墙钟时间预算，因此恢复不会把单策略 episode 预算成倍扩张。
  • REA-M 使用路由记忆和异常门，不在线调用 System 2；REA-A 让智能体选择初始及恢复策略；REA-V 使用路由记忆，并在策略返回边界调用视觉 judge。单策略基线等价于关闭升级，blind retry 则无条件重试。
  • RoboTwin 的 VLA 扩展把初始指令、图像和机器人状态编码为特征，为每个候选策略预测成功分数并选择最高者；加入代码策略只需增加对应策略头，不改变统一执行接口。REA 改的是策略外部的运行时、路由和恢复机制，而不是 VLA 的网络结构、训练目标或权重。

实验与结果

  • 在 LIBERO-Pro 的 60 个任务、每任务 50 个测试种子、共 3000 个 episode 上，REA-M 达到 95.9% 成功率，超过开发集上选出的最佳单体方法 Agents SDK + GPT-6 的 94.7%，绝对提升 1.2 个百分点；配对 McNemar 检验为 86:51、\(p=0.004\)，95% 配对区间为 \([+0.4,+1.9]\) 个百分点。
  • 在程序完全对齐的 37 个任务上，REA-M 为 95.3%，Agents SDK + GPT-6 为 93.7%，差值 1.6 个百分点（54:25，\(p=0.001\)，95% 区间 \([+0.6,+2.5]\)）；全任务结果距离后见式逐任务 oracle 的 96.9% 仅 1.0 个百分点。
  • REA-M 每次成功平均使用 1003 个控制步，Agents SDK + GPT-6 为 1343 步，减少约 25%；论文同时报告其控制时间比 Agents SDK + GPT-6 少 17%，且比阻塞式 advisor 少 25%。REA-A 同样达到 95.9%，但需要平均每个 episode 约 1 次在线模型调用，说明把大脑放回 dispatch 路径没有带来成功率收益。
  • 恢复实验中，REA 对 ASPIRE 与零样本 GPT-6 策略分别带来 8.6 和 7.0 个百分点提升；视觉 judge gate 相比异常 gate 提升 3.1 个百分点（\(p=0.022\)），代价是每次成功耗时达到后者的 2.1 倍。
  • RoboTwin 2.0 的独立 100-episode 研究中，REA 的纯 VLA 路由达到 84%，VLA+代码混合池达到 86%，高于最强单 VLA 基线 MEDex 的 80%。迁移实验还报告：BEHAVIOR-1K 为 27/50，对照 Agents SDK 的 25/50，但差异不显著；另一组 RoboTwin 迁移测试为 97/200，对照 Codex CLI 的 75/200；真实 Unitree G1 完成 8/10 次试验。
  • 失败检测的必要性来自具体案例：论文展示了一个无异常的 LIBERO-Pro episode，第一次 Evo 和随后 Fix 均未完成任务，judge 连续拒绝后，第二次 Evo 最终把碗放到炉子上；单靠异常触发无法启动这类恢复。

局限与可以继续做的

  • REA 的主要证据来自预先生成的候选策略池及固定开发集路由统计；按任务聚合的成功率未必能覆盖同一任务内部由视觉状态、物体布局或语言扰动造成的多模态差异。可在 LIBERO-Pro 上直接比较“逐任务 route memory”与“基于当前观测的动态路由”，并按扰动轴报告校准误差与失败类型。
  • LIBERO-Pro 主结果中的策略池并非所有 60 个任务都与单体基线完全一致：严格对齐仅覆盖 37 个任务，其余 23 个任务使用 harness 程序替代 Codex 程序，或以 ASPIRE Evo 替代 ASPIRE Fix。尽管论文单独报告了对齐子集，解读全套 1.2 个百分点增益时仍应区分“路由收益”和“候选池差异”。
  • 视觉 judge 带来成功率提升，但每次成功耗时为异常 gate 的 2.1 倍；其阈值与提示词又依赖 216 个开发标签。可进一步测试小型本地 VLM、时序状态估计器或不确定性触发器，仅在高风险边界调用大模型，并报告误停、漏检和重复执行三类代价。
  • RoboTwin 的 VLA 对比只有 100 个 episode，BEHAVIOR-1K 只有 50 个 episode，Unitree G1 只有 10 次试验；这些结果证明了接口可迁移性，但不足以确认跨机器人、长时任务及安全关键场景中的稳定收益。后续应扩大真机种子与任务类型，并测量碰撞、恢复次数、judge 延迟和墙钟预算超限率。
  • 当前阶梯最多按固定顺序运行三个候选，且从当前状态接续；前一策略可能把环境带入另一策略训练分布之外。可增加状态可恢复性检测、策略间交接契约和安全回滚，并专门构造“已部分完成但不可逆”的任务评估升级是否会放大损害。
  • 论文没有报告对 π0、π0-FAST、π0.5 或 OpenPI 的直接集成。可将冻结的 OpenPI 执行器作为 System 0，在不微调权重的条件下比较单 π 策略、多个 π 检查点路由、π+代码混合池及 judge 恢复，验证收益是否来自通用运行时而非特定策略库。
实验设置
  • LIBERO-Pro：MuJoCo/robosuite；使用 goal、object、spatial 六个套件在 task 与 swap 扰动下形成 60 个任务，不包含 Long 套件以及 object、language、environment 扰动轴。
  • LIBERO-Pro 主评测：每任务测试种子 1–50，共 3000 个 episode；每个 episode 上限 4000 控制步、900 秒；路由方法最多运行三个策略。
  • LIBERO-Pro 跨方法研究：种子 1–10，共 600 个 episode；困难恢复子集包含 6 个任务，每任务 12 个种子，其中 8 个是参考 Fix 策略的失败种子。
  • System 0 的 LIBERO-Pro 策略为冻结 Python 程序，调用 SAM 3、ContactGraspNet、PyRoki 逆运动学及阻塞式运动原语；沙箱禁止可访问模拟器内部状态的标识符。
  • 策略生成来源包括 ASPIRE Fix/Evo、Codex + GPT-6、Agents SDK + GPT-6，以及每任务两个样本的零样本 GPT-6；ASPIRE 程序由 Codex gpt-5.6-sol 生成，其他策略生成方法使用高推理强度的 gpt-6-astra。
  • 完整策略库中 legacy pool 为每任务一个 Codex 或 harness 程序，并在 59 个任务上提供 ASPIRE 候选；加入 SDK 后总计 179 个程序。
  • 路由记忆仅使用开发 episode：匹配子集和跨方法研究使用种子 51–60，完整评测使用种子 61–70；legacy 程序共运行 1190 个开发 episode，SDK 程序共 600 个。
  • 视觉 judge：匹配子集使用 deepseek-v4-flash-vision-exp，完整 LIBERO-Pro 使用其后继 deepseek-flash；阈值和提示词在 216 个开发标签上冻结后再进入测试。
  • REA-A 路由模型为 jev-1.13.0；阻塞式 advisor 每 8 个、每段 100 控制步的 segment 推荐一次策略，并在返回前阻塞路由器。
  • 统计协议：LIBERO-Pro 配对成功率采用精确 McNemar 检验和配对 95% 区间；时间差使用按任务聚类的 bootstrap 区间；主要对比在同一问题内经 Holm 校正后仍成立。
  • RoboTwin 2.0：SAPIEN 双臂环境；VLA/代码研究使用固定 100 个场景，包括 50 个 clean 和 50 个 randomized episode；另有独立的 200 场景迁移研究。
  • BEHAVIOR-1K：R1Pro、OmniGibson/Isaac Sim，包含 5 个 pick-up 任务。
  • 真机平台包括 Unitree G1 与 AlohaMini2；G1 的最终成功由操作员判定。所给原文未披露真机传感器配置、控制频率及 10 次试验的具体种子协议。
AI导读和推荐理由
  • 推荐这篇的核心原因不是它提出了新的 VLA，而是它把研究焦点从“再训练一个更强策略”转向“如何让多个冻结策略、代码控制器和慢速大模型在同一闭环系统中可靠协作”。
  • 论文同时报告成功率、控制步数、控制时间、静默失败恢复及跨仿真/真机迁移，适合用来设计 π 系列部署时的运行时基线与系统级评测，而不能被当作 π 模型能力本身的提升证据。

与π系列的关系

  • REA 不是 π0、π0-FAST、π0.5 或 OpenPI 的新模型、训练方法或微调方案。原文仅在相关工作中把 π0 列为快速 VLA 的代表，没有报告对 π0、π0-FAST、π0.5 或 OpenPI 的直接集成、检查点对比或专项消融。
  • 对 π 系列最直接的关系是接口层：冻结的 π/OpenPI 策略可以作为 System 0，以其原生动作块和频率闭环执行；REA 在其外部增加 System 1 路由、边界 judge 和共享预算恢复，而不需要改变策略骨干、动作头、训练数据或损失函数。
  • 它与固定快慢频率的双系统模型也不同：REA 的 System 1 不生成动作，System 2 可以是独立开发的智能体，System 0 可以混合 VLA、程序和全身控制器；“无运行中策略等待大脑”是运行时约束，而非端到端模型结构。
  • RoboTwin 的 84% 纯 VLA 路由与 86% VLA+代码结果说明异构策略池可能有互补性，但原文没有说明七个 VLA 中是否包含 π 系列，因此不能把这两个数字解释为 OpenPI 或 π0 的实测收益。

对Austin研究的启发

  • 在 OpenPI 执行器外增加统一的 Run(policy, remaining_steps, remaining_time) 契约，让动作块只在安全 segment 边界归还控制权；先保持 π 权重冻结，以隔离运行时收益与模型微调收益。
  • 构建至少四组闭环对照：单 OpenPI 策略、按任务 route memory、多检查点或多策略动态路由、OpenPI+代码策略混合池；统一任务种子、初始状态、单一最终 scorer 和总时间/步数预算。
  • 对引导场 \(G\) 或条件遵循任务，不要只记录最终成功率；在动作块边界监控条件偏离、部分完成、不可逆状态和 judge 置信度，分别统计静默失败、误判完成、无效升级及升级后恢复率。
  • 将 judge 从固定“每次策略返回都调用”改成风险触发：用执行器内部不确定性、动作块进度、视觉状态变化和安全约束先做轻量筛选，仅在分歧或停滞时调用 VLM judge，以检验能否保留恢复收益并降低 2.1 倍的时间代价。
  • 为策略交接保存标准化状态摘要，包括机器人本体状态、已完成子目标、剩余条件、动作历史和安全约束；测试 π 策略接续代码策略、代码策略接续 π 策略时是否出现分布外状态或重复操作。
  • 把“最佳单体策略”之外再加入后见 oracle，并报告实际路由与 oracle 的差距。REA 在 LIBERO-Pro 上距 oracle 仅 1.0 个百分点，这类指标能直接判断下一步应优先改底层策略、路由器还是完成判定器。

一句话总结

REA 由新加坡国立大学 HPC-AI Lab、InfRec/Cardinal AI Lab、加州大学伯克利分校、东京大学、中科院深圳先进技术研究院及香港科技大学相关作者提出，以路由记忆、边界 judge 和共享预算升级统一调度冻结策略，在 3000 个 LIBERO-Pro episode 上取得 95.9% 成功率、较最佳单体策略高 1.2 个百分点并减少约 25% 控制步数，但尚未直接集成或验证 π0、π0.5 与 OpenPI。
