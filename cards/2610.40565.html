问题

  • 现有机器人仿真虽能并行运行、即时重置、提供稠密奖励与完整状态，但覆盖的真实工作类型和物理现象仍然有限；增加新场景通常依赖专家手工建模，难以随训练规模同步扩展。
  • 通用物理引擎并不自动带来任务所需的真实性：液体表面张力、化学反应、布料摩擦、切割与焊接等机制可能缺失或未经定量验证；编码智能体直接生成的仿真还可能用动画替代物理、产生穿模或允许奖励漏洞。
  • 本文主要研究自动构建、审计和使用机器人仿真，而不是提出新的机器人策略架构。评测以闭环仿真交互为主：策略根据相机图像和机器人反馈连续发出控制命令；默认受限策略看不到仿真内部状态，完整特权状态仅用于学习实验。
  • 作者目标是把仿真开发转化为可随编码智能体能力扩展的任务，自动生成兼顾真实性、可解性、运行速度、可配置性与抗漏洞性的环境，并以此扩大机器人训练和评测的任务覆盖。

Overview of Gym-Anything for Robotics. Phase~1: We select 120 simulations grounded in U.S.\ GDP data, covering the most valuable physical work across occupations and everyday life, and build 25 of them. Phase~2: A creation agent builds each simulation in code and produces evidence of its quality, which four audit agents check against our criteria. Phase~3: A task creation agent proposes tasks of targeted difficulty, which six audit agents check, and each task runs with many robots and variations. Phase~4: Models learn from privileged simulation state through in-context learning, coaching, and code policies that train VLAs.
  • 整体流程为“经济活动选择 → 仿真创建与审计 → 任务创建与审计 → 策略评测和学习”：先从美国职业、经济价值和日常活动数据中分解原子物理动作，再选择能够覆盖高价值动作及其物理能力的仿真，最后由编码智能体实现环境、任务和验证器。
  • 每个仿真由场景对象、物理模型、机器人、相机和物理引擎组成，并支持替换单臂、双臂或人形机器人，以及改变物体位姿、外观和物理参数；这些变化改变场景和初始状态，但不改变任务语义。
  • 作者用四类共十项标准定义“合格仿真”，覆盖物理与视觉真实性、现实相关性、参数依据、交互动力学、可解性、运行速度、框架集成与配置、文档，以及对数值不稳定和非物理动作漏洞的鲁棒性。
  • 创建智能体负责调研现实流程、实现仿真，并提交渲染、物理测量和允许使用“幻影力”的辅助演示等证据；四个独立审计智能体分别检查四类标准，其中一个审计器主动通过合法机器人动作寻找仿真漏洞。问题返回创建智能体修复，循环共进行三轮，所有智能体共享跨仿真的经验记忆。
  • 任务表示为初始仿真状态、自然语言指令和验证函数。验证函数直接读取物理状态，输出二值成功标签及区间为 \([0,1]\) 的进度—结果奖励；成功必得 1，失败时仍可按已完成部分给予进度分，减少纯终局奖励的稀疏性。
  • 任务由创建智能体按目标难度生成，再由六个具有人工整理检查表的独立审计智能体检查可解性、奖励正确性等属性。与手工环境基线相比，本文改变的是仿真和任务的生成、证据与审计流程，而不是统一替换被评测策略的骨干。
  • 在学习阶段，作者利用仿真特权状态设计四条路径：跨重复尝试的上下文学习；特权教师以定性语言提示指导无特权学生；模型从自身的特权经历中自辅助学习；以及由特权代码策略跨场景生成示范，训练只观察图像和本体状态的 \(\pi_{0.5}\)。

实验与结果

  • Gym-Anything for Robotics 最终构建了 RoboWorld：25 个仿真、25 个测试强化学习环境和 175 个训练环境，共 200 个环境，覆盖制造、建筑、餐饮、实验室和物流等现实工作领域。
  • 完整 RoboWorld 测试基准上，即使表现最好的前沿模型，任务成功率仍为 0%，平均奖励仅为 0.06；这说明模型虽然偶尔取得局部进展，却没有完成任何完整测试任务。
  • 在论文划分的较简单任务子集上，最佳模型成功率达到 32%。该结果不能直接视为完整基准成绩，因为任务难度和评测子集不同。
  • 仿真对比显示，RoboWorld 不只调用通用求解器，还针对任务所依赖的物理机制进行实现和检查。例如葡萄酒倾倒环境采用 2 mm 的 DFSPH 粒子，每瓶包含 93,750 个粒子，并加入润湿、接触线钉扎、瓶内空气与间歇涌流等机制；该环境包含 12 项物理检查和 12 个对抗评估案例。原文将其与 SoftGym、ManiSkill2 等最接近环境的论文报告项进行比较，并指出这些先前条目未报告定量物理检查。
  • 作者报告，重复尝试的上下文学习可提升任务表现，加入特权状态后学习更快；特权教师提示、自身特权经验，以及代码策略生成示范训练 \(\pi_{0.5}\) 也都带来显著改善。但所提供正文未包含这些实验的完整表格和具体增益数字，因此无法核对各方法的绝对成绩、提升幅度或统计显著性。

局限与可以继续做的

  • 当前只实现了 GDP 驱动选择流程得到的 120 个候选动作组中的 25 个；美国 GDP、职业数据和时间使用数据强调经济价值，并不等价于全球地域覆盖、安全价值或家庭辅助需求覆盖。
  • 仿真通过代码、物理测量和多智能体审计提高可信度，但审计智能体与创建智能体在本文实例中均使用同一模型家族，可能共享盲点；通过审计也不代表已经证明仿真到真实世界的迁移效果。
  • 完整基准成功率为 0% 能体现难度，但也可能使不同模型主要依靠平均奖励区分；仍需检查奖励是否与真实技能进步一致，以及不同任务的分数是否具有可比较性。
  • 论文展示了通过代码策略训练 \(\pi_{0.5}\) 的直接联系，但给定原文没有披露真实机器人部署、仿真到真机迁移率、示范规模、视觉域随机化细节或与真实示范训练的受控比较，相关结论目前限于仿真学习价值。
  • 可继续做的实验包括：为部分环境制作独立的真实物理装置，逐项比较轨迹、接触力、材料状态和成功判据；引入不同模型或人工专家作为交叉审计器；报告各任务多随机种子置信区间、失败类型和奖励—成功率相关性。
  • 面向 π/OpenPI，可将同一策略置于机器人替换、位姿、外观和物理参数的组合分布偏移下，分别评测闭环恢复、跨形态控制和奖励漏洞；再用“代码策略示范量 × 场景变化量 × 少量真实数据量”的网格消融，检验仿真示范真正带来的泛化收益。
实验设置
  • 论文：Pranjal Aggarwal、Sean Welleck，Carnegie Mellon University；arXiv:2610.40565v1，2026 年 10 月。
  • 候选范围：从美国职业任务、职业经济价值、日常活动时间等公共数据中选择 120 个动作组；本文实现其中 25 个仿真。
  • RoboWorld：25 个测试环境、175 个训练环境，共 200 个强化学习环境，分布于 25 个仿真。
  • 机器人：每个仿真指定默认机器人，并可从共享目录替换为单臂、双臂和人形机器人。
  • 观测：相机图像及关节位置等机器人反馈；动作可以是关节目标、末端执行器运动或夹爪命令。
  • 闭环协议：每一步策略接收观测并发出机器人命令；物理时间只在执行命令时推进，模型思考时间不会改变场景；episode 在策略结束或耗尽时间预算时终止。
  • 受限访问：仅提供任务指令、相机图像、机器人反馈和允许使用的控制命令文档；除特别说明外，被评测智能体使用该模式。
  • 特权访问：额外开放物体位姿、接触力、材料状态等完整仿真状态及任务评估信息，用于上下文学习、教师—学生、自辅助学习和代码策略实验。
  • 奖励：验证函数根据物理状态计算二值成功和 \([0,1]\) 奖励；成功奖励固定为 1，非成功轨迹可获得进度分。
  • 仿真审计：一个创建智能体、四个仿真审计智能体，进行三轮创建—审计—修复；各智能体共享跨仿真经验记忆。
  • 任务审计：一个任务创建智能体和六个独立任务审计智能体，依据人工整理的检查表审查任务。
  • 智能体实例：创建与审计智能体均为 Claude Opus 5.5，通过 Claude Code 等编码智能体 harness 运行。
  • VLA 实验：特权代码策略生成跨场景示范，用于训练仅观察相机图像和机器人本体状态的 \(\pi_{0.5}\)。
  • 给定正文未披露各前沿模型的完整名单、检查点、推理超参数、每任务 episode 数、多随机种子设置、计算硬件，以及 \(\pi_{0.5}\) 示范数量和训练超参数。
AI导读和推荐理由
  • 推荐重点不在“又一个 VLA 架构”，而在 VLA 训练与评测所依赖的环境供给：论文把仿真、任务、验证器、物理证据和漏洞测试统一成可由编码智能体迭代的工程闭环。
  • RoboWorld 完整测试成功率为 0%、平均奖励仅 0.06，说明当前前沿模型在包含复杂材料和长程物理交互的任务上仍存在明显能力缺口；同时，特权状态和代码策略为构造学习信号提供了具体接口。

与π系列的关系

  • 本文不是 \(\pi_0\)、\(\pi_0\)-FAST、\(\pi_{0.5}\) 或 OpenPI 的新模型架构，也没有声称修改 π 系列的视觉语言骨干、动作表示或训练目标；核心贡献是自动化仿真生成、审计、任务构建和学习数据生成框架。
  • 与 π 系列的直接实验关系来自 \(\pi_{0.5}\)：特权代码策略读取仿真内部状态，在不同场景中生成示范，再训练只能观察图像与机器人本体状态的 \(\pi_{0.5}\)。这相当于把特权信息用于教师侧数据生产，而非在部署时赋予 VLA 不现实的状态输入。
  • 给定原文没有报告对 \(\pi_0\)、\(\pi_0\)-FAST 或 OpenPI 的实验，也没有足够信息判断训练实现是否基于 OpenPI；因此不能把该方法视为已经在整个 π 系列上验证的通用插件。
  • 对 π 系列更重要的启发是环境与监督层：同一任务可以跨机器人形态以及物体位姿、外观和物理变化运行，适合检验 VLA 是否学习了可迁移的视觉—动作规律，而非记住固定场景或利用奖励漏洞。

对Austin研究的启发

  • 可先把 OpenPI 执行器封装到 RoboWorld 的统一控制接口中，明确关节目标、末端增量和夹爪命令之间的适配层；保持策略权重不变，单独测量接口适配、机器人替换和动作频率对成功率的影响。
  • 若研究包含引导场 \(G\) 或显式条件遵循，可将任务验证器拆成连续进度、终局成功、安全约束和物理质量四类信号，逐步检查策略究竟是在遵循指令，还是只在优化容易利用的局部奖励。
  • 建立闭环监控面板，至少记录接触力、材料状态、控制饱和、碰撞、非有限值、动作停滞和奖励突变；把四类仿真审计及对抗漏洞测试纳入每次环境或控制器更新后的回归测试。
  • 设计“受限学生—特权教师”消融：学生始终只看图像和本体状态，教师分别提供语言提示、目标状态摘要、代码示范和无教师四种条件，比较样本效率、闭环恢复能力及在未见物理参数上的泛化。
  • 对代码策略生成的数据，应按场景变化而非随机帧切分训练集与测试集，并单独测试未见机器人、未见外观和未见物理参数；否则高分可能来自相邻场景泄漏，而非真正的跨场景泛化。

一句话总结

Carnegie Mellon University 的 Aggarwal 与 Welleck 用创建智能体、4 个仿真审计器和 6 个任务审计器构建了含 25 个仿真、200 个环境的 RoboWorld，完整测试上最佳前沿模型仍为 0% 成功率、平均奖励 0.06，并以特权代码策略生成示范训练 \(\pi_{0.5}\)。
