深读｜ReFocus

📐 原版模型结构图详解🤖 向 AI 提问本篇论文原文 ↗

问题

  • 长时程操作中，后续子任务接收的是策略自身执行产生的状态；早期偏差会逐步累积，因此即使某个子任务完成，也不代表策略能从该状态继续完成全任务。
  • 仅使用二元终局奖励的在线 RL 无法区分“早期即失败”和“已完成大部分流程但末段失败”，因而既难定位瓶颈，也难为局部进展提供有效学习信号。
  • 反复执行完整任务会浪费交互预算：每次练习后段技能都必须先重做前序步骤，且前序失败可能使真正的瓶颈阶段根本得不到训练。
  • 本文覆盖 LIBERO-Long、RoboCasa365 仿真基准与三个真机长时程任务；从 SFT 初始化的 π0.5 策略出发，通过闭环环境交互在线更新完整策略，而非冻结 π0.5 后仅训练一个外接模块。目标是在有限交互下识别并集中练习任务瓶颈，同时把局部改进转化为更高的全任务成功率。

方法

  • 全局强化学习（Global RL）：左侧以视觉观测与任务指令 $o_k$ 输入共享 VLA 策略 $\pi_\theta$，输出动作块 $a_k$ 并执行完整任务轨迹；策略由 SFT 初始化，通过全任务反馈持续更新。
  • 任务 DAG 与进度奖励（Task DAG / Progress Reward）：调度器 $\mathcal S$ 构建 $G=(V,E)$，节点为子任务、边为前置依赖。首次合法完成由 $z_{v,k}\in\{0,1\}$ 标记，形成进度状态 $p_{v,k}=\sum_{j=0}^{k}z_{v,j}$；第 $s$ 阶段预算 $B_s=2/S$，故 $r_k^{\mathrm{prog}}=\sum_s\sum_{v\in V_s}(B_s/n_s)z_{v,k}$。
  • 自适应瓶颈练习（Adaptive Practice Windows）：中部 Scheduler 根据子任务完成率定位薄弱阶段并输出练习窗口；三种 rollout 模式连接窗口内 Local RL 与完整任务执行，Milestone Rewards 在窗口中提供比终局奖励更细粒度的反馈。
  • 多轮交替优化（Multi-round Training）：右侧在 Global RL 与 Local RL 间循环，共享并更新同一 $\pi_\theta$；每轮的全任务反馈及练习成本写入 History Buffer，作为下一轮窗口选择依据。

Illustration of ReFocus. (a) Global RL uses task DAGs to assign progress rewards and track subtask completion. (b) The Scheduler selects Adaptive Practice Windows for bottleneck practice. Three rollout modes connect local practice with full-task execution, while milestone rewards provide finer feedback. (c) Multi-round training alternates Global and Local RL. Full-task feedback and practice costs are recorded in the history buffer to guide subsequent practice.
  • ReFocus 以多轮方式交替执行 Global RL 与 Local RL：前者从正常初始状态训练完整任务并收集进度轨迹，调度器据此诊断瓶颈；后者围绕瓶颈构造练习窗口并继续更新同一个 VLA 策略，随后重新进行正常起点的全任务评测。
  • 每个任务被表示为子任务依赖 DAG。具有相同前置条件的子任务组成一个阶段，阶段内可按任意顺序完成；只有满足依赖关系后的首次有效完成才会获得奖励，从而避免越过前置条件或重复完成带来的错误计分。
  • DAG 进度奖励将固定的任务级奖励预算平均分配给各阶段，再在阶段内部平均分给子任务。这样，一个阶段不会仅因被拆成更多子任务而获得更高总权重；终局成功奖励仍被保留，与进度奖励共同用于 Global RL。
  • 调度器比较失败验证轨迹的进度序列，寻找反复停滞的最早阶段，并检查对应视觉观测以描述失败动作；随后结合历史缓冲区中的旧窗口、交互成本及全任务成功率变化，决定保留、修改或跳过下一轮局部练习。
  • Adaptive Practice Window 由进入阶段、目标阶段和交互预算组成，并附带可验证的细粒度里程碑。Local RL 混合三类 rollout：从可恢复状态直接练瓶颈的 normal window、从正常任务起点执行至窗口目标的 prefix window，以及从恢复状态继续向全任务终点执行的 suffix window，以兼顾局部练习、前序状态分布和后续可延续性。
  • Global RL 与 Local RL 均使用 PPO，并共同更新 actor 与 critic；两阶段没有更换基础策略，主要区别在于 rollout 分布和奖励定义。Local RL 用里程碑奖励替换目标子任务原有份额，避免重复计奖，同时继续记录 DAG 子任务进度。

实验与结果

  • 在 LIBERO-Long 上，SFT 初始化的 π0.5 成功率为 90.6%，ReFocus 达到 97.8%；两者使用同一 π0.5 基础模型，结果表明瓶颈导向的多轮在线 RL 仍能在较高起点上继续提升。
  • 在 RoboCasa365 Composite-Seen 上，π0.5 从 39.3% 提升至 51.3%。该基准包含更丰富的厨房活动、物体运输与电器交互，提升发生在明显更低、也更具挑战性的初始成功率上。
  • 真机 BreadBaker 任务中，SFT π0.5、RECAP 和 ReFocus 的成功率分别为 30%、70% 和 95%；在 StackBowl 与 PickFruit 上，ReFocus 均达到 100%，对应的 RECAP 结果分别为 90% 和 85%。
  • 三个真机长时程任务的总体成功率为 98.3%，图中报告的 RECAP 总体结果为 81.7%。这些结果支持“针对瓶颈增加练习”可以改善完整流程，而不只是提高被截取片段内的局部完成率。
  • 所提供原文在表 1 开头处截断，因此无法核对 Sparse-RL、SimpleVLA-RL、PolicyTrim、StructRL 的逐项结果、按 horizon 分组数字、消融实验及交互效率数据；不据此补写未展示的数值。

局限与可以继续做的

  • ReFocus 依赖预先构造的任务 DAG、可验证的子任务条件、可恢复训练状态和里程碑检查。现实开放环境中若对象状态不可观测、重置成本高或成功条件难以程序化验证，这套局部练习接口可能难以直接部署。
  • 瓶颈诊断与窗口设计依赖 frontier LLM。所给正文没有报告调度器模型、提示词稳定性、调用成本、人工复核比例或错误 DAG 对最终性能的敏感性，因此尚不能判断收益中有多少依赖特定 LLM 或人工工程。
  • 仿真实验证据来自 LIBERO-Long 和 RoboCasa365 Composite-Seen，真机证据来自三个任务；对新机器人形态、未见任务、动态干扰以及更长任务链的外推仍缺少证据。真机任务的试验次数和置信区间也未出现在所提供片段中。
  • 当前结果主要报告成功率，但未在所给内容中展示达到这些结果所需的总环境步数、恢复状态构建成本、LLM 调度成本及 wall-clock 时间。可进一步在等环境交互、等重置次数和等计算预算下比较完整任务 RL、固定窗口课程与自适应窗口。
  • 可执行的后续实验包括：人为注入 DAG 边错误或里程碑检测噪声，测量调度鲁棒性；分别移除 prefix、suffix 和 normal window，验证三类 rollout 的作用；在不可精确恢复状态的真机上用生成式重置或近邻状态检索替代 entry bank；增加“局部窗口成功但后续任务失败”的专门指标，检查局部提升能否稳定传递至全任务。
实验设置
  • 仿真基准：LIBERO-Long，共 10 个桌面长时程任务；RoboCasa365 Composite-Seen，选取 16 个涉及物体运输和电器交互的厨房任务。
  • 基础策略：在各基准官方 demonstrations 上进行 SFT 的 π0.5；随后在所选任务上训练共享策略。
  • 对照方法：SFT π0.5、Sparse-RL、SimpleVLA-RL、PolicyTrim、StructRL；所有 RL 基线使用相同训练配置。Sparse-RL PPO 使用二元成功奖励，StructRL 是子任务级进度奖励基线。
  • 优化：Global RL 与 Local RL 均使用 PPO，同时更新策略 actor 和 critic；优势估计采用 GAE，并对有效优势进行归一化。正文还提到 Flow-SDE transition ratio，具体推导位于未提供的附录 C.1。
  • Global RL 的进度奖励总预算为 2，平均分给各阶段，再在阶段内平均分配；另加权重为 \(\lambda_{\mathrm{succ}}\) 的全任务成功奖励，但所给片段未披露该权重数值。
  • 诊断协议：Global RL 期间每 5 次更新执行验证；记录进度序列、视觉观测和全任务结果，用于瓶颈诊断与练习窗口选择。Local RL 期间同样每 5 次更新记录评测，并在阶段结束后从正常任务起点进行全任务评估。
  • Local RL rollout：按概率混合 normal、prefix 和 suffix 三种窗口模式；具体概率、每阶段更新次数、训练轮数及 PPO 超参数未出现在所提供片段中。
  • 评测规模：LIBERO-Long 每个任务使用 50 个初始场景，RoboCasa365 每个任务使用 100 个初始场景。
  • 真机任务：BreadBaker、StackBowl、PickFruit；所给片段未披露机器人型号、相机与传感器配置、控制频率、每项评测次数和训练交互预算。
AI导读和推荐理由
  • 这篇论文的价值不在于提出更大的 VLA 骨干，而在于补足长时程在线 RL 的训练组织问题：何时跑完整任务、如何知道卡在哪里，以及如何把有限交互集中到真正限制成功率的阶段。
  • 对 π 系列实践者而言，它给出了一个可外挂到 SFT 策略之上的闭环适配框架，并通过正常起点复测约束局部训练，避免只在可恢复窗口内“刷高”局部成功率。

与π系列的关系

  • ReFocus 不是新的 π 系列基础模型，而是以 SFT 初始化的 π0.5 为基础策略，在其上进行在线 PPO 适配；训练过程中更新完整策略及 critic，并非冻结 π0.5、只训练奖励头或外部控制器。
  • 本文改变的是训练与数据采样层：增加任务 DAG、阶段均衡进度奖励、LLM 瓶颈调度器、可恢复状态 entry bank、三类练习窗口和跨轮历史缓冲；没有声称修改 π0.5 的核心 VLA 架构。
  • 所给原文没有显示 ReFocus 基于或直接比较 π0、π0-FAST，也没有表明其代码建立在 OpenPI 上；因此不能把它视为 π0.5 或 OpenPI 的官方扩展。
  • 与单纯扩大 SFT 数据相比，ReFocus 针对的是策略部署后自身诱导的偏离状态：通过在线交互发现 demonstrations 未覆盖的失败阶段，再以局部练习和全任务复测形成闭环。

对Austin研究的启发

  • 在 OpenPI 或自有 π0.5 执行器外增加统一的 progress-event 接口：每个 action chunk 后输出已满足的子目标、前置条件、首次完成标记和当前阶段，使奖励、诊断与评测共用同一份可审计状态。
  • 将引导场 \(G\) 或条件遵循信号映射为 DAG 里程碑，但应保持“阶段总奖励固定”的原则，避免把一个阶段拆得更细就获得更多奖励；同时记录错误顺序完成、重复完成和前置条件未满足三类事件。
  • 为闭环评测同时维护三组指标：窗口内目标成功率、从真实前序状态进入窗口后的成功率、正常起点全任务成功率。只有三者共同改善，才能说明针对性练习没有产生恢复状态过拟合。
  • 可先做一个低成本消融：在相同环境步预算下比较二元终局奖励、DAG 进度奖励、固定瓶颈窗口和 ReFocus 式自适应窗口；再分别关闭 prefix 与 suffix rollout，定位收益来自密集奖励还是状态分布衔接。
  • 真机执行器应把状态恢复失败、里程碑检测置信度和窗口超时作为显式监控信号；低置信度时退回完整任务 rollout，而不是让调度器依据可能错误的进度记录继续分配预算。

一句话总结

浙江大学与香港大学作者提出的 ReFocus 以 π0.5 为初始化，通过 DAG 进度奖励和自适应瓶颈练习交替执行全局与局部 PPO，使 LIBERO-Long、RoboCasa365 和三个真机长时程任务的成功率分别达到 97.8%、51.3% 和总体 98.3%。
