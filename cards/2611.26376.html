深读｜Alignment Drives Reuse

📐 原版模型结构图详解🤖 向 AI 提问本篇论文原文 ↗

问题

  • 机器人交互经验被机器人构型、运动学、坐标系、观测格式和动作接口割裂：同一个数值动作在不同控制器上可能产生不同物理效果，使跨基准、跨硬件汇总经验远比语言或视觉数据困难。
  • 现有 VLA 通常从特定设置的轨迹示教中学习动作预测，场景、指令或机器人变化后可能明显退化；交互式程序技能方法虽能利用执行反馈修复策略，但既有工作大多局限于固定工作站、固定执行接口，或为不同基准分别学习技能库。
  • 论文研究仿真操作基准中的闭环程序执行：agent 根据任务、观测和交互历史生成 Python 程序，技能依据实测动作结果和场景变化进行分支与检查；不提供参考轨迹示教，也不更新底层 agent model 的权重，但会修改共享程序技能、库函数、动作接口及其编排策略。
  • 作者目标是先对齐几何表示、执行契约和任务定义，再让多个基准与机器人上的交互反馈共同改进一个可复用技能库，并在冻结后迁移到未见任务、场景、机器人和基准。

方法

  • 动机与输入异构性（a）：不同任务、机器人形态与基准产生观测 $o_t=(I_t,d_t,q_t)$ 及机器人专属动作 $a_t^{(r)}$；UniCraft 不直接共享底层控制，而是抽取可跨边界复用的语义操作技能，统一“做什么”，保留“如何执行”的本体差异。
  • 表示与接口对齐（b）：Camera Adapter 以 $K,R_t,\mathbf t_t$ 将像素深度反投影为统一局部坐标 $\mathbf p_t^w=R_t(d_tK^{-1}[u,v,1]^\top)+\mathbf t_t$，生成带类别、包围框、位置和尺度的 typed Objects；同时用 $R^{\mathrm{tcp}}=[\hat{\mathbf x}_g,\hat{\mathbf y}_g,\hat{\mathbf z}_a]$ 对齐夹持与接近方向。
  • 技能—编排联合精炼（b）：对齐后的对象状态输入共享技能库 $\mathcal S$ 与编排策略 $\pi$；$\pi$ 选择并组合技能，技能输出设备无关的目标位姿、容差和终止条件，再由 Native Adapter 映射为各机器人原生动作 $a_t^{(r)}$。训练利用多回合反馈联合更新技能及其编排，每个模型混合 3 个基准、6 种本体的 2,700 条 rollout。
  • 复用与迁移评测（c）：同一 $\mathcal S$ 和 $\pi$ 仅切换原生适配器即可跨机器人组合执行；在 5 个基准、10 种本体上比较基线与技能复用，并零样本迁移至 4 台新机器人和 2 个未见基准，其中 robosuite 迁移结果统计于 2,000 个仿真步。

  • 整体流程：把各基准任务转换为统一 case → 将视觉区域反投影到统一度量坐标系并构造类型化对象 → agent 编排共享技能与库函数 → adapter 将能力式动作转换为机器人原生控制命令 → 收集成功判定、执行轨迹和步数 → Reviser 根据跨任务反馈提出补丁并验证。
  • 统一几何表示：每个 episode 固定局部世界坐标系和向上的 \(z\) 轴；相机提供内参及拍摄时位姿，将像素与深度反投影为米制三维点。对象同时携带图像框、可见区域的位置与尺度，供共享技能直接使用。
  • 统一工具约定：以接近轴和夹爪闭合轴定义 TCP 朝向，使抓取方向由目标几何表达，而不是隐含在某台机器人的坐标约定中；已有工具坐标的基准沿用其定义，其余机器人由手指装配几何恢复该约定。
  • 能力式执行契约：系统区分 Skill、无设备命令的 Library、抽象 Action 和机器人原生 Adapter。Action 不只规定函数签名，还规定坐标系、单位和基于设备实测状态的完成谓词；“命令已发出但未达到目标”仍判为失败。
  • 共享逻辑与硬件解耦：技能代码不包含机器人专属的坐标变换、运动学或控制器常量；adapter 负责从统一目标到原生工具坐标、逆运动学、控制输入及实测结果的完整转换。论文改变的是技能与硬件之间的接口层，没有训练统一的低层动作预测网络。
  • 反馈驱动联合修订：共享配置包括技能、动作接口、库函数和编排策略。LLM Reviser 从失败中诊断共性机制并提出补丁；候选修改必须在检查案例上逐案例不退化且至少改善一例，若成功率不变，再比较配对成功 rollout 的归一化执行步数。最终配置冻结后用于部署和迁移。

实验与结果

  • 每个训练用 agent model 在 LIBERO-PRO、RoboTwin 2.0 和 RoboCasa365 上交错执行 2,700 次学习 rollout，共享经验覆盖 180 个任务、300 个任务—机器人组合和 6 种机器人构型。
  • 从第 1 到第 3 个 epoch，未见场景与留出任务的汇总成功率在三个训练 agent model 上分别呈现以下提升范围：LIBERO-PRO 为 9–28 个百分点，RoboTwin 2.0 为 10.8–13.3 个百分点，RoboCasa365 为 3.1–14.4 个百分点。这些是绝对百分点增量；所给原文没有披露各模型的起止成功率，不能据此还原最终绝对成功率。
  • 泛化评测覆盖 66 个未见场景 case 和 36 个留出任务；连续 epoch 的提升支持“异构经验在接口对齐后可以共同改进共享技能”，而不只是记忆训练任务。
  • 学习结束并冻结技能与编排策略后，同一套实现零样本迁移到 4 种新机器人构型、未参与训练的 robosuite 与 RoboDojo 两个基准，并扩展到 5 个额外 agent model；全文总体评测范围为 5 个基准、10 种机器人构型。
  • 提供的原文片段未包含完整结果表、逐任务数据、外部基线的数值对照和具体失败案例，因此无法核对每个迁移组合的绝对成功率，也不能判断提升是否集中在少数任务。

局限与可以继续做的

  • 现有证据来自 LIBERO-PRO、RoboTwin 2.0、RoboCasa365、robosuite 和 RoboDojo 等仿真基准；所给正文没有报告真实机器人部署，因此 adapter 对传感噪声、标定漂移、接触不确定性和硬件安全约束的鲁棒性仍未验证。
  • 方法依赖统一对象几何、深度、相机标定、TCP 约定及基准原生成功判定。感知区域错误、遮挡或不准确的深度会直接污染共享技能输入，而当前片段没有独立量化感知误差的影响。
  • 论文证明了任务、基准和机器人层面的复用，但没有给出专门的因果消融来区分几何对齐、工具坐标、能力接口、交错采样和 Reviser 各自贡献；也未展示对条件置零、反向或交换后的行为变化。
  • 可以构造严格的组合矩阵：对物体、目标、场景和机器人做交叉覆盖，只留出特定“物体×目标”或“技能×机器人”组合；同时与非交错训练、各基准独立技能库及移除统一坐标约定的版本对照，判断收益是否确由组合复用产生。
  • 可以在真实机械臂上加入 adapter 契约测试和故障注入，包括位姿偏差、抓取未闭合、目标滑移、导航误差及放置失败，并分别统计故障检测、重规划、恢复成功率和额外步数，而不只统计最终任务成功。
实验设置
  • 训练基准：LIBERO-PRO、RoboTwin 2.0、RoboCasa365。
  • 零样本迁移基准：robosuite、RoboDojo。
  • 总体范围：5 个基准、10 种机器人构型；训练阶段使用其中 3 个基准和 6 种构型，迁移阶段增加 4 种新构型。
  • 训练数据：每个 agent model 进行 2,700 次学习 rollout；覆盖 180 个任务和 300 个任务—机器人组合。
  • 泛化集合：66 个未见场景 case、36 个留出任务。
  • 训练轮次：报告第 1 至第 3 个 epoch 的变化；原文片段未说明每个 epoch 的精确 case 划分及 rollout 数量。
  • 模型协议：底层 agent model 不做权重更新；修改对象是程序技能、动作接口、库函数和编排策略。训练结束后保留配置被冻结，用于零样本部署。
  • 训练模型与迁移模型：主要结果覆盖 3 个训练 agent model，并在 5 个额外 agent model 上测试迁移；图注出现 Gemini、DeepSeek 和 MiniMax，但所给片段未披露完整检查点名称及版本。
  • 示教协议：不向系统提供参考轨迹示教；参考轨迹仅用于确定执行长度。案例 \(c\) 的 rollout horizon 为 \(H_c=\lceil2d_c\rceil\)，其中 \(d_c\) 是参考执行长度。
  • 反馈内容：基准原生成功判定、执行轨迹和环境步数；步数按各基准原生控制频率统计。
  • 补丁接受标准：所有被检查案例均不得降低经验成功率，且至少一例改善；成功率轮廓不变时，以配对成功 rollout 的归一化步数是否减少作为效率标准。
  • 传感与表示：相机提供内参、拍摄时旋转和平移以及深度；对象包含二维框和可见区域的三维位置、尺度。
  • 平台性质：提供的正文描述的是基准仿真实验，没有披露真机传感器、物理控制频率或真实机器人试验次数。
AI导读和推荐理由
  • 推荐这篇的核心原因不是它提出了新的低层控制网络，而是它把“能否复用经验”追溯到表示与执行接口是否对齐，并用跨任务、跨基准、跨机器人的交错 rollout 检验这一假设。
  • 对组合泛化研究尤其有价值的是其数据组织方式：训练覆盖 300 个任务—机器人组合，另设未见场景和留出任务，并在冻结技能后测试新机器人与新基准，形成了比随机 episode 划分更明确的复用证据链。

与本项目关系

  • UniCraft 的统一对象几何与能力式接口，和 Austin 项目的 A/F 接口都试图把任务意图转换成可跨场景复用的几何条件；但两者表达内容不同：UniCraft 主要统一对象位置、尺度、接近/抓取方向、程序化技能和硬件动作契约，并没有显式表示“物体应如何变化”的 \(F/G\)，也没有证明策略持续追随一个动态目标场。
  • 最直接的联系是组合数据设计。UniCraft 通过跨任务、机器人和基准交错采样，再用未见场景、留出任务、新机器人和新基准评测复用；这可直接映射为 Austin 项目的“物体×目标×场景”交叉覆盖与未见组合测试。
  • 与 Austin 当前使用 OpenPI（π0/π0.5）作为执行器的路线相比，UniCraft 没有更新 VLA 权重，而是让 agent 编排可执行程序，并通过 adapter 调用原生控制器。因此它能启发外围接口和数据协议，但不能直接证明 π0/π0.5 会理解或遵循 G。
  • 论文使用实测动作结果判定执行契约，能够识别“抓取命令发出但实际未抓到”等失败；不过它没有报告 G 的置零、反向或交换消融，也未专门回答抓到物体后是否持续跟随目标、是否送到正确目标，以及成功是否依赖熟悉的物体—目标关联。

启发

  • 将 LIBERO 数据组织成显式组合矩阵，对物体、目标、场景和 G 方向做交叉采样；分别留出“新物体—已见目标”“已见物体—新目标”和“已见元素的新配对”，避免随机划分掩盖关联记忆。
  • 为 A/F 或 G 建立类似 UniCraft Action 的执行契约：除接口形状外，明确坐标系、单位、更新时间和可观测完成条件；放置任务至少记录物体是否被抓住、是否朝目标持续移动、是否进入目标容差区及释放后是否保持稳定。
  • 在相同初始场景和相同语言指令下，运行正确 G、置零 G、反向 G、交换目标 G 四组闭环测试；按轨迹阶段统计物体速度在 G 方向上的投影，而不只看最终成功率，从而区分“真正遵循几何条件”与“把 G 当作任务 ID”。
  • 用冻结的 π0/π0.5 做执行器时，分别比较按基准独立训练、混合但不对齐接口、对齐后交错训练三种协议；若只有第三种在留出组合上改善，才能更有力地支持“对齐促进复用”。
  • 建立失败回放集，覆盖抓取成功但放错目标、目标移动后不再跟随、物体中途滑落和释放失败；候选接口或策略修改采用逐 case 不退化约束，并额外报告恢复成功率与归一化额外步数。

一句话总结

悉尼大学与南京大学提出的 UniCraft 通过统一几何、能力式执行契约和交错反馈学习复用程序技能，使第 1 至第 3 个 epoch 的未见场景与留出任务汇总成功率在三个训练基准上提升 3.1–28 个百分点，并在冻结后迁移到 4 种新机器人和 2 个未见基准。
