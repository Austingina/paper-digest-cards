SOAR: Training-Free Rank-Consistent Rollout Compression for Latent World Model Planning

📐 原版模型结构图详解🤖 向 AI 提问本篇论文原文 ↗

问题

  • 潜在世界模型依靠 CEM 在每次决策中采样数百条动作序列，并通过 Transformer 自回归展开；以公开的 JEPA-WM 为例，原始预算下单次规划即使在 H100 上也需 20–50 秒，闭环重规划开销很高。
  • 现有加速方法多沿用 ViT/VLM 的空间 token 剪枝思路，重点保持视觉特征内容；但 CEM 实际只消费候选动作的代价排序并选出精英集，特征或代价值本身的误差未必会改变规划结果。
  • 固定空间预算无法覆盖不同任务：Push-T 对接触区域的空间细节敏感，而 MetaWorld Reach 更依赖前一帧提供的运动信息；相同压缩方式可能在一个任务上安全、在另一个任务上失效。
  • 论文在冻结已发布世界模型检查点、保持原始 CEM 预算的闭环规划设定下，目标是无需训练和任务标签，按每次决策所需的排序保真度自适应压缩 rollout，在维持成功率的同时降低规划延迟。

方法

  • 稠密规划基线（Dense Rollout）：Figure 1 是冗余性诊断总览，而非网络拓扑图。规划器以完整上下文帧和全部空间位置执行潜在世界模型 rollout，所得任务成功率作为归一化基准；纵轴 “Success relative to dense” 表示压缩方案成功率与稠密成功率之比，$r_{\mathrm{rel}}=S_{\mathrm{compressed}}/S_{\mathrm{dense}}$。
  • 四类剪枝轴（Four Pruning Axes）：子图 (a) 分别沿 Table 1 定义的四个 rollout 剪枝维度减少计算，并以横轴 speedup 衡量加速比。各曲线刻画压缩强度增加时 $r_{\mathrm{rel}}$ 的变化，用于辨别哪些中间计算存在冗余、哪些删减会破坏规划排序与最终成功率。
  • 空间位置减半（Halving Spatial Positions）：子图 (b) 将潜在特征中的空间 token/位置数由 $N$ 压缩至 $N/2$，比较 Push-T 与 MetaWorld Reach 上的相对成功率；该操作直接降低世界模型 rollout 中空间特征传播与预测的计算量。
  • 上下文帧丢弃（Dropping the Context Frame）：同一子图进一步移除历史 context frame，仅保留更精简的 rollout 条件输入。两项消融与 Dense 对照共同说明：空间位置和上下文均可能包含可压缩冗余，但不同任务对两类信息的敏感度并不一致。

  • 整体流程是：从第一次 CEM population 中抽取少量候选动作序列，以多个嵌套 token 预算分别 rollout，比较压缩预算与完整预算下的候选排序，再选择满足排序一致性要求的最小预算执行该次决策的完整 CEM 搜索。
  • SOAR 不以预测特征重建误差为准，而以候选代价的 Spearman 排名相关性为在线压缩信号；其依据是 CEM 只需由代价排序得到最低成本的 \(K\) 个精英候选。
  • 所有 rollout 的第 0 步保持完整计算，因为它是唯一直接读取真实观测的预测步，其误差会被后续自回归预测和最终规划代价持续继承。
  • 第 1 步以后不再重新计算前一帧，而是复用其注意力 key/value 缓存；这既保留依赖时序上下文的任务所需信息，也消除重复处理上下文帧的开销。
  • 后续步骤只压缩“最新帧”的空间位置，并使用固定、嵌套的棋盘格 token 子集。论文的诊断实验表明，均匀空间覆盖通常比 VLM 式显著性选择更可靠，关键更多在于“何时压缩”而非“选择哪些 token”。
  • 方法不训练新预测器、不微调原有检查点，也不改变原始 CEM 的候选规模、精英数和迭代预算；相对稠密规划器增加的只是每次决策一次轻量排序探测与 KV 缓存接口。

实验与结果

  • 在 7 项导航与操作任务、总计超过 80,000 个闭环 episode 上，SOAR 在达到稠密规划成功水平时取得 \(2.3\times\) 加速；进一步压缩至 \(2.5\times\) 加速时，仍保留稠密规划器 98% 的成功率。这里的成功率以同批、同初始状态和目标下的稠密模型为参照。
  • 在线探测仅占总规划时间的 1%–2%，说明直接在每个决策点检查排序一致性没有抵消 rollout 压缩带来的收益。
  • 50% 空间预算下，VLM token 选择规则并不可靠：ToMe、FastV、DART、DivPrune 的七任务平均成功率分别为稠密模型的 0.51、0.66、0.34、0.63；随机选择为 0.60。规划感知的 CostGrad 和 Guard-rank 提升到 0.84 和 0.89，但仍未达到稠密水平。
  • 压缩时机比 token 选择更关键：所有步骤均保留 128 个位置时，平均成功率为稠密模型的 0.90、加速 \(2.17\times\)；仅将第 0 步恢复为完整计算后，平均达到 1.03、加速 \(1.82\times\)。相反，仅完整计算最后一步时只有 0.66，表明末端补算无法修复早期自回归误差。
  • 不同任务呈现互补失败模式：保留一半空间位置时，Push-T 仅保留 0.73 的稠密成功率，而 MetaWorld Reach 为 1.08；移除上下文帧时，二者分别为 0.95 和 0.18。这支持按决策自适应预算，而不是为所有任务设置一个固定压缩率。
  • 单独使用上下文 KV 缓存即可在不知道任务类型的情况下匹配稠密成功率并获得 \(1.76\times\) 加速；直接删除上下文虽在导航和推动任务上基本无损，却会让 MetaWorld Reach 损失 31–43 个成功率百分点、Reach-Wall 损失 12–30 个百分点。

局限与可以继续做的

  • 证据集中于 JEPA-WM 系列的冻结检查点及其两帧滑动窗口结构；尚不能据此确认排序一致性预算在其他世界模型、长视频上下文、扩散式 world action model 或端到端 VLA 中同样有效。
  • 任务共 7 项，涵盖导航、平面推动、机械臂到达和放置，但原文所给实验均为既定基准中的闭环评测；提供的正文未披露真实机器人部署、传感噪声、动态遮挡或跨场景分布外测试结果。
  • SOAR 用少量候选的 Spearman 相关性近似完整 population 的排序稳定性。相关性高并不严格保证前 \(K\) 个精英集合完全相同，尤其可能漏掉少数接近精英边界、但会影响后续 CEM 分布更新的候选。
  • 当前压缩变量主要是最新帧的 token 数量，固定棋盘格强调均匀覆盖，却未显式利用空间几何、障碍边界或接触拓扑。可进一步比较 Spearman 阈值、精英集合重合率与 top-\(K\) 边界 margin，并在低 margin 时自动回退到稠密 rollout。
  • 面向导航可增加长程 GoalNav/VLN、跨楼层和动态障碍实验，并分别报告 SR、SPL、碰撞率、规划延迟及排序相关性；还可将预算控制扩展为分层策略，例如高层世界模型自适应 token 预算、低层局部控制器维持固定频率。
  • 可在真实机器人或在线 SLAM 系统中测试缓存失效机制：当定位重置、回环闭合、观测突变或场景动态度超过阈值时清空 KV 缓存并恢复完整第 0 步，检验加速是否会被状态估计误差放大。
实验设置
  • 模型：发布的 JEPA-WM 检查点，评测时冻结。
  • 视觉编码器：多数任务使用冻结的 DINOv2 ViT-S/14，将图像编码为 \(16\times16\) patch 特征网格；RoboCasa 使用 DINOv3 ViT-L/16。
  • 世界模型：动作条件 AdaLN Transformer；Maze、Wall、Push-T、MetaWorld 使用 6 层、宽度 384，RoboCasa 使用 12 层、宽度 1024。
  • 上下文：预测器使用两帧滑动窗口；第 0 步读取真实观测，后续步骤输入前一帧与最新帧。
  • 任务：Maze、Wall、Push-T、MetaWorld Reach、MetaWorld Reach-Wall、RoboCasa Reach、RoboCasa Place，共 7 项。
  • CEM：每轮 \(N=300\) 个候选、\(K=10\) 个精英；Maze、Wall、Push-T 运行 30 轮，MetaWorld 与 RoboCasa 运行 15 轮。
  • 规划时域：\(H=6\) 或 \(H=3\)，提供的正文片段未逐任务列出对应关系。
  • 代价：最终预测特征与目标特征之间的 L2 距离；可用时包含本体感觉信息。空间剪枝时，目标特征限制到相同的保留位置。
  • SOAR 探测：每个决策从第一次 CEM population 中取 \(M=16\) 个候选，在 3 个嵌套 token 预算下展开，以相对完整预算的 Spearman 相关性和阈值 \(\tau\) 选择最小预算；提供的正文片段未给出三个预算的具体 token 数及 \(\tau\) 数值。
  • 评测次数：前 5 项任务每次评测各运行 96 个 episode，两个 RoboCasa 任务各运行 32 个 episode；各方法共享初始状态与目标，进行配对比较。
  • 统计：报告相对同批稠密模型的任务平均成功率；95% 区间来自按任务分层、10,000 次重采样的配对 bootstrap。
  • 延迟：单张 H100、FP32，测量一次完整规划调用，包括编码、辅助计算及全部 CEM 搜索；以同任务稠密延迟归一化并报告其倒数为加速比。
  • 总规模：超过 80,000 个闭环 episode。
  • 训练与标签：SOAR 无额外训练，不使用任务标签。
AI导读和推荐理由
  • 推荐这篇的核心原因不是又一种空间 token 剪枝，而是它把规划压缩的目标从“特征是否逼真”改成“候选动作的排序是否稳定”，直接对齐采样式规划器真正使用的信号。
  • 论文同时给出较完整的失败诊断：真实观测进入模型的首步不能省、上下文可能不能删但可以缓存、固定预算会因任务动力学不同而失效。这些结论对世界模型导航的系统设计比单一加速数字更有价值。

与现有VLN/SLAM对比

  • 主流 VLN 通常直接预测动作或航点，经典 GoalNav/SLAM 则依赖显式地图、位姿估计和搜索；SOAR 不提出新的语言 grounding、地图表示或定位模块，而是加速基于潜在视觉特征和 CEM 的 world-model rollout。因此，它与 VLN/SLAM 更多是规划计算层面的互补关系，不能由本文结果推出 VLN 的 SR/SPL 或 SLAM 的轨迹误差改善。
  • 相比固定分辨率的潜在地图或统一空间剪枝，SOAR按每次决策的候选排序稳定性分配计算：容易区分的决策使用更少 token，排序敏感的决策保留更高预算。这类似给局部规划器增加一个在线“计算充分性”检查器。
  • 工程权衡是每次决策需要额外运行 16 个候选、3 档预算的探测，但其测得开销仅为规划时间的 1%–2%；收益则是在冻结模型和原始搜索预算不变时实现最高 \(2.3\times\) 的稠密成功率等效加速。
  • 对 SLAM 系统尤其值得注意的是上下文策略：直接删除历史帧可能破坏速度或动态状态推断，而 KV 缓存可以保留历史信息并避免重算。不过论文没有显式建图、回环检测、位姿图优化或几何一致性模块，也未报告 ATE/RPE。
  • 对 VLN 而言，论文没有语言指令、长程记忆或语义地图实验；其排名一致性原则可迁移到航点候选或 frontier 候选排序，但这一迁移尚未在本文验证。

对Austin启发

  • 在空间几何表示上，可把当前固定棋盘格扩展为“均匀覆盖优先、几何风险补充”的嵌套预算：基础层覆盖整张特征网格，增量层加入深度不连续处、可通行区域边界、窄通道及潜在碰撞区域，同时保持预算间严格嵌套以便复用计算。
  • 在分层规划接口上，可让高层 world model 输出候选子目标及其排序置信度，低层控制器继续使用固定频率执行；当 Spearman 相关性低、top-\(K\) 交集不足或精英边界 margin 过小时，高层自动提高 token 预算或缩短重规划间隔。
  • 在 SLAM/世界模型耦合中，可将 KV 缓存与地图版本绑定：正常帧间更新复用缓存，发生回环闭合、位姿大幅修正、跟踪丢失或动态场景突变时使缓存失效，避免历史特征与更新后的几何坐标系不一致。
  • 在跨场景泛化评测中，不只记录平均 SR/SPL，还应按场景复杂度、窄通道比例、动态物体数量和定位不确定性分桶，联合记录所选 token 预算、排序相关性、规划时延与失败类型，检查方法是否真的把更多计算分配给困难决策。
  • 可增加一个安全回退消融：比较 Spearman 阈值、top-\(K\) 精英集合重合率及二者结合的触发规则；导航中一旦压缩排序与稠密排序不一致且候选涉及碰撞风险，就恢复稠密 rollout，而不是继续采用最小预算。

一句话总结

上海交通大学提出的 SOAR 以候选动作排序一致性在线选择 latent world-model rollout 的 token 预算，在 7 项导航与操作任务、超过 80,000 个闭环 episode 上以 \(2.3\times\) 加速达到稠密规划成功水平，并在 \(2.5\times\) 加速下保留 98% 的成功率。
