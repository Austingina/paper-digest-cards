问题

  • 细粒度操作不仅要识别正确物体，还要区分瓶盖/瓶身、指定字母或开关颜色等局部目标，并在接近、接触、抓取、搬运、插入等连续阶段中保持指令一致；局部定位误差或中途偏离都可能导致失败。
  • 通用预训练机器人策略具有视觉与动作先验，但未必能直接满足 MetaFine 对局部感知、指令切换、视觉扰动和多阶段执行的精细要求；单次长动作预测也容易在状态变化后积累误差。
  • 论文采用已知任务 ID 的设定，为五项任务选择独立适配的策略，并以短动作块、获取新观测后重新规划的方式闭环执行。所给正文未明确说明官方环境属于仿真还是真机，也未完整披露所有骨干参数是否冻结。
  • 作者目标是通过任务专用适配、精细视觉定位和反馈纠错，提高现有视觉—语言—动作模型在五类细粒度操作任务上的综合成功表现与视觉鲁棒性。

方法

🧭 模型结构图逐模块详解（本地千问 Qwen 精读）
  • 输入与任务路由（Task Routing）：每回合重置时，已知任务 ID $\tau\in\{1,\ldots,5\}$ 以 one-hot 门控选择独立策略 $\pi_{\theta_\tau}$。输入为指令 $\ell$ 与历史 $\mathcal O_t$；单帧观测 $o_t=(I_t^{\mathrm{base}},I_t^{\mathrm{wrist}},q_t)$，含两幅 $512\times512$ RGB 图像及九维关节位置。
  • 双骨干与任务分支（Two Backbone Families）：五个任务被归入两类骨干并保留 task-specific branches。T1/T5 由 DINOv2 提取双视角空间特征，Heatmap/Visibility Heads 输出关键点及置信度；指令进一步选择 T1 的 cap/body 分支或 T5 的目标字母分支。
  • 特征融合与动作生成（DiT Policy）：预测视觉特征、$q_t$、历史动作及目标 one-hot 在两帧窗口内融合；T1 还汇聚瓶盖中心与夹爪邻域特征。Diffusion Transformer 对高斯噪声动作块迭代去噪，生成 $\mathbf A_t=(a_t,\ldots,a_{t+H-1})$，其中 $a_t\in\mathbb R^8$ 控制七个机械臂关节和夹爪。
  • 执行与闭环重规划（Replanning）：MoP 为硬路由 $\pi_{\mathrm{MoP}}=\sum_{k=1}^5\mathbf1[\tau=k]\pi_{\theta_k}$；每次仅产生一条动作流，执行前 $K\le H$ 步后获取新观测并重规划。T2/T4 取 $H=K=10$，T3 取 $H=10,K=5$。

FineCraft as a task-routed mixture of policies (MoP). The task ID selects one independent task policy for the rollout. Two backbone families summarize five task instances, including their task-specific branches. The selected policy generates one action stream and replans from new observations.
  • 整体流程为：任务 ID 选择对应策略，策略接收基座相机、腕部相机、机器人本体状态和语言指令，预测动作块；系统只执行其中一部分动作，再用新观测重新预测。
  • 五项任务共享观测—动作接口，但不是一个统一策略：瓶身/瓶盖抓取与字母插入使用 DINOv2 特征、关键点/可见性预测和 DiT 动作生成；杯子搬运、开关切换与方块分类使用任务专用 LoRA 适配的预训练 π0.5。
  • T1 将瓶盖和瓶身建成两个独立分支，由指令选择目标。瓶盖分支额外汇聚瓶盖中心和夹爪附近的局部视觉特征；瓶身分支使用从学习策略困难状态开始的专家续接数据，并排除专家介入前的学习器动作。
  • T1 重规划时从三个候选动作块中选择与上一动作块未执行部分差异最小、且代价低于阈值的候选，以减少相邻规划之间的动作跳变；若均不满足阈值，则使用第一个样本。
  • T2、T3、T4 保留 π0.5 的视觉—语言及动作模块接口，通过每任务独立的 LoRA 权重和动作归一化统计进行适配；这改变的是任务专用低秩参数，而非训练一个跨任务共享的组合策略。
  • T5 由通用策略、收尾策略和 C/o/L 字母专用纠错策略组成。阶段分类器连续两次给出正预测后切换到收尾策略，停滞监测器可进一步触发纠错；阶段只按“通用→收尾→纠错”单向切换。

实验与结果

  • FineCraft 在 MetaFine 官方五任务评测中总分为 0.878，排名第四；官方感知、理解、行为三轴均值分别为 0.860、0.887、0.887。
  • 相比组织方发布的 π0 参考均分 0.430，FineCraft 提高 44.8 个百分点，并在五项任务及每个评测维度上均高于该公开参考。该数字是对组织方公开结果的比较，不是论文重新训练 π0 得到的同场消融。
  • 杯子搬运 T2 的感知、理解和行为均为 1.000；方块分类 T4 总分 0.987，其中行为分 0.983，覆盖连续完成三次放置的阶段进度，而不只是首次抓取。
  • 其余任务中，开关切换 T3 得分 0.925，瓶部件抓取 T1 得分 0.796；最困难的字母插入 T5 得分 0.681，其中感知仅 0.594、理解和行为均为 0.725。T5 相对 π0 参考的感知与理解分别提升 56.9 和 67.5 个百分点，但相机与光照扰动仍比固定场景中的指令变化更难。
  • T1 本地诊断中，在相同排序的场景种子上，瓶身指令成功 70/80，瓶盖指令成功 72/80；加入瓶盖相机和光照扰动测试后，共计 720 次 rollout，感知分 0.874、综合分 0.883，且相机扰动下的成功曲线面积低于光照扰动。
  • T3 的本地继续训练实验覆盖三个开发组；每个模型在 60 个场景上执行 540 次 rollout，平均分由 0.841 提升到 0.894。不过该结果同时改变了训练数据规模和训练时长，不能单独归因于其中一个因素。

局限与可以继续做的

  • 系统依赖已知任务 ID 路由到五个独立适配策略，T1 和 T5 内部还包含目标分支或纠错子策略；因此结果不能证明存在一个可复用、可组合的统一交互表示，也不能证明对未见任务组合的零样本泛化。
  • 官方结果与组织方发布的 π0 数字比较，但论文没有报告同一代码、数据和训练预算下的 π0、π0.5 全量微调、LoRA 及 DINOv2-DiT 对照；各组件的独立贡献因而难以拆分。
  • T3 的适配研究将扩充数据与继续训练绑定在一起；T5 也没有分别报告阶段分类器、停滞检测器和字母专用纠错策略的消融，现有证据不足以量化每个机制带来的增益。
  • 论文评估了固定场景下改变指令，但没有置零、反向或交换几何条件的干预实验，也没有测试策略是否在执行全过程持续服从条件，而非仅把指令当作任务或分支 ID。
  • 可继续构造“物体×目标×方向×场景”的交叉训练矩阵，并留出未见组合；在相同初始状态下交换目标或运动场，逐帧评估目标跟随、错误放置、重规划恢复和停滞恢复，而不只统计最终任务分数。
  • 可将 FineCraft 的 π0.5-LoRA 执行器作为强基线，额外输入统一的 G 或 A/F 条件，并比较“仅语言”“语言+G”“G 置零/反向/交换”以及视觉预测 G，检验预训练策略是否真正利用交互几何。
实验设置
  • 任务：T1 瓶盖/瓶身抓取、T2 杯子搬运、T3 红/蓝开关切换、T4 方块分类与连续放置、T5 指定字母插入。
  • 官方评测采用 MetaFine 的感知 P、理解 U、行为 B 三轴：感知为相机与光照扰动成功曲线的归一化面积均值；理解在固定场景种子上改变指令；行为对单阶段任务评最终成功，对多阶段任务评归一化阶段进度。
  • 单任务分数为 (P+U+B)/3，总分为五个任务分数的均值；T1、T3、T5 的行为分复用理解评测结果。
  • 官方数字取自 2026 年 10 月 24 日更新的最终公开排行榜中 HITSZ Robotics 条目；比较基线为组织方发布的 π0 参考分数。
  • 每步观测包含两张 512×512 RGB 图像，分别来自基座相机和腕部相机，以及由九个关节位置表示的本体状态；动作是七个机械臂关节加一个夹爪控制量，共八维。
  • T1/T5 使用 DINOv2 空间特征、关键点与可见性预测头和 DiT；动作模型使用两帧观测历史。T1 分为瓶盖与瓶身模型，T5 另有通用、收尾和 C/o/L 专用纠错策略。
  • T1 分支和 T5 通用策略预测 16 步动作，每次执行 2 步后重规划；T5 收尾策略预测 8 步，各子策略同样每次执行 2 步。
  • T2、T3、T4 使用 π0.5 加任务专用 LoRA 和独立动作归一化统计。T2、T4 各使用 300 条示范、训练 30,000 次更新。
  • T2、T4 的动作预测与执行长度均为 H=K=10；T3 预测 H=10 步、执行 K=5 步后重新观测。
  • T3 数据包含 864 条轨迹和 88,059 个动作帧；红、蓝指令在相同物理场景中示范，另加入相机与光照扰动场景，训练与推理使用明确的目标颜色提示。
  • T3 本地诊断的训练与评测场景种子互斥；每个模型在三个开发组共 60 个场景上执行 540 次 rollout。
  • T1 本地测试包含 80 次瓶身、80 次瓶盖指令测试，以及 560 次瓶盖相机/光照扰动测试，共 720 次 rollout。
  • 所给正文未披露 LoRA 秩、学习率、批大小、全部优化器设置、候选动作块代价阈值、具体 π0.5 检查点名称，以及官方评测环境的仿真/真机属性。
AI导读和推荐理由
  • 推荐这篇的主要原因不是它提出了统一组合表示，而是它给出了 π0.5 经任务专用 LoRA 适配后，在搬运、开关切换和多次放置任务中的强执行器基线，并展示了短动作块闭环重规划的实际效果。
  • 论文同时提供固定场景改变指令、瓶盖/瓶身目标切换、视觉扰动和停滞纠错等评测，可用于思考“策略是否真的遵循条件”；但其任务 ID 路由和独立策略结构限制了对组合泛化的证明力。

与本项目关系

FineCraft 与 Austin 项目的直接联系在于：它可作为 OpenPI/π0.5 执行器的参考基线，并说明持续重规划有助于搬运、多次放置和困难状态恢复。差距也很明确：FineCraft 没有统一的 G 或 A/F 交互几何接口，瓶盖/瓶身与不同任务主要通过任务 ID、目标 one-hot 或独立权重切换，也未通过 G 置零、反向、交换等干预证明策略持续遵循几何条件；其数据与评测也未覆盖系统性的物体×目标留出组合。

启发

  • 在同一初始场景中设置不同目标或相反运动方向，分别测试语言、G、A/F 对最终放置位置的控制；除成功率外，记录每次重规划后策略输出是否继续朝目标收敛。
  • 以 FineCraft 的 π0.5-LoRA 配置为执行器基线，增加 G/A-F 条件后做四组严格对照：正常条件、置零、方向反转、跨样本交换；若动作仅随条件类别离散切换而不随几何连续变化，应视为任务 ID 化而非真正条件遵循。
  • 将训练数据整理为物体×目标×场景的交叉覆盖矩阵，显式留出未见“物体—目标”组合；分别报告抓取成功、送达正确目标、连续目标跟随和失败恢复，避免抓到物体后错误放置仍被中间阶段分数掩盖。
  • 借鉴 T5 的阶段与停滞监测，但避免绑定字母专用纠错策略：可用统一的接近、接触、输运、释放阶段监控器触发重规划，再测试它能否跨物体和目标复用。
  • 对视觉预测的 G 增加在线一致性检查：比较预测物体运动与实际观测到的物体轨迹，当方向持续偏离或物体停止运动时触发重新定位、目标重选或恢复策略。

一句话总结

来自哈尔滨工业大学（深圳）、西安交通大学、Shenzhen Loop Area Institute 与 HITSZ Robotics 的作者团队，以任务路由的 DINOv2-DiT 和 π0.5-LoRA 策略、短动作块重规划及专用纠错机制在 MetaFine 获得 0.878 总分和第四名，较公开 π0 参考提高 44.8 个百分点，但尚未证明统一交互表示上的组合泛化。
