深读｜RTPolicy

📐 原版模型结构图详解🤖 向千问提问本篇论文原文 ↗

问题

  • 闭环机器人操作依赖滚动生成动作块；在异步推理中，延迟越高，新观测越晚影响当前轨迹，机器人越难及时修正累积偏差。
  • 现有视觉运动策略的开销来自三个相互耦合的环节：大型视觉骨干、多视角视觉条件，以及扩散或流模型的多次迭代采样。已有加速方法往往只减少动作生成步数，没有同步压缩视觉编码与多视角条件路径。
  • 论文同时考察 RoboTwin 2.0 仿真基准和真实双臂平台，采用多视角 RGB 与机器人状态输入，闭环、异步流式执行动作块；DINOv3 ConvNeXt 视觉编码器在策略训练中冻结。
  • 作者目标是在保留精细操作能力的同时，联合降低视觉编码、多视角条件和动作生成成本，使策略能够在边缘设备上实时运行。

方法

  • 整体流程：多视角图像先经冻结的 DINOv3 ConvNeXt 提取稠密特征，再经视角感知融合与视觉压缩形成紧凑条件；机器人状态前缀、压缩后的视觉 token 和流时间共同条件化 DiT，输出未来动作块。
  • 视角感知融合：为每个相机视角加入可学习的 view embedding；先用参数共享的单层 Transformer 分别处理各视角，再用另一单层 Transformer 在拼接后的稠密序列上进行跨视角交互。跨视角融合发生在压缩之前，以免过早丢失空间对应信息。
  • 视觉压缩：将融合后的 token 按视角恢复为空间网格，分别执行残差下采样和自适应平均池化，再拼接成紧凑视觉条件。虽然压缩逐视角进行，其输入已包含其他视角的信息。
  • 动作生成：DiT 将固定的机器人状态前缀与带噪未来动作序列拼接，并通过 cross-attention 接收视觉 token；训练采用 flow matching，只监督未来动作位置，不对状态前缀加噪或计算预测损失。
  • 低步数推理：从高斯噪声初始化未来动作槽，使用均匀 Euler 积分；每次网络评估前都把状态前缀重新固定，仅更新未来动作，默认用 4 次 DiT 评估生成一个动作块。
  • 相对已有方法的变化：RTPolicy不是对 π0、π0.5 或 OpenPI 的轻量化改造，也未保留其策略骨干；它独立采用冻结的 DINOv3 ConvNeXt、专门的多视角融合/压缩模块和流匹配 DiT。相较只减少去噪步数的方法，它还改造了视觉条件路径。

实验与结果

  • 在 RoboTwin 2.0 的 50 项 clean2clean 单任务评测中，RTPolicy 平均成功率为 52.26%（表中四舍五入为 52.3%），高于官方排行榜中的 π0 46.4%，绝对提升约 5.86 个百分点；RDT、ACT 和 Diffusion Policy 分别为 34.5%、29.7% 和 28.0%。
  • 十项代表任务的平均成功率为 63.0%，对比 π0 的 58.8%。RTPolicy 在 beat block hammer 上为 76%、π0 为 43%；在 click alarmclock 上为 76%、π0 为 63%。但 blocks ranking RGB 和 blocks ranking size 仅为 5% 和 3%，说明排序类任务仍明显困难。
  • 三视角真实平台中，视觉条件由 900 个稠密 token 压缩到 12 个 token，数量减少 75 倍；真实双臂任务的平均成功率为 72.0%。原文所给节选未列出真实任务名称、逐任务成功率和评测次数。
  • INT16 部署时，端到端推理在 RDK S600 上为 30.35 ms / 32.9 Hz，在 RDK S100 上为 149.72 ms / 6.7 Hz。论文摘要称其支持异步流式闭环推理，但所给正文未提供不同延迟下的轨迹纠偏量化对照。
  • 积分步数消融中，2–6 步的五任务平均成功率处于 80.6%–82.0%，4 步为 81.4%；10 步反而为 78.6%。4 步仅使用10步调度器 40% 的 DiT 评估次数，支持其效率工作点，但并非该表成功率最高的设置，最高值是5步的 82.0%。

局限与可以继续做的

  • 外推风险：RoboTwin 主结果采用“每项任务单独训练、单独评测”，并以50任务联合预训练作为初始化，不能直接证明一个统一策略具备跨任务指令跟随、零样本泛化或 π0.5 式开放世界能力。
  • 证据边界：真实平台只报告 72.0% 的总体平均值；所给原文没有披露任务构成、每项试验次数、置信区间、失败类型，以及遮挡、相机扰动或场景变化下的鲁棒性，难以判断统计稳定性。
  • 基线可比性：50任务主表中的 π0、RDT、ACT 和 DP 数字来自官方排行榜，而不是本文在完全统一代码、训练预算与硬件下复现；作者只在局部消融中对 DP、VO-DP 使用相同示范数据比较。
  • 压缩上限尚不清楚：900→12 token 显著降低条件长度，但正文节选没有给出 token 数量、跨视角融合顺序及无压缩模型之间的完整精度—延迟曲线。可进一步测试每视角 1/2/4/8 个 token，并按小物体、遮挡和精确接触任务分层报告退化。
  • 可继续做的实验：把该压缩模块接到 OpenPI 执行器或 π 系列动作专家之前，在冻结原策略与端到端微调两种条件下，对比原始视觉 token、RTPolicy 压缩 token 的成功率、观测到动作延迟和扰动恢复时间；同时加入相机掉帧、单视角缺失及异步到达测试，验证 view embedding 是否真正支持稳健多视角融合。
实验设置
  • 仿真基准：RoboTwin 2.0，50项双臂操作任务；clean2clean 单任务协议在 Aloha AgileX 上进行。
  • 数据：每项目标任务使用官方发布的50条 clean demonstrations；先在50任务语料上联合预训练，再为每项目标任务单独微调。数据扩展消融另使用每任务100条或200条示范。
  • 观测与动作：左、右、头部三个相机提供分辨率为 \(240\times320\) 的 RGB 图像；机器人状态为14维，策略预测关节动作轨迹。
  • 评测协议：每个任务训练一个检查点，并只在该任务上评测；主结果每任务评测100个 episode，使用基准规定的随机种子，再对任务成功率取平均。
  • 视觉模型：冻结 DINOv3 ConvNeXt 编码器；视角内 Transformer 和跨视角 Transformer 均为单个 block，视角内模块在各相机间共享参数。
  • 真实平台视觉条件：\(V=3\)、每视角 \(P=300\) 个稠密 token、压缩后每视角 \(m=4\) 个 token，压缩特征宽度 \(d_c=1024\)，最终条件形状为 \(12\times1024\)。
  • 动作模型：DiT 隐藏维度2048、8个 block、32个注意力头；默认采用4步均匀 Euler 积分。
  • 训练：AdamW、bfloat16 混合精度、batch size 256；联合预训练300K步、学习率 \(2\times10^{-4}\)，任务微调30K步、学习率 \(2\times10^{-5}\)。
  • 流匹配采样：\(\tau=(0.999-s)/0.999\)，其中 \(s\sim\mathrm{Beta}(1.5,1.0)\)；动作噪声为标准高斯。
  • 时间范围：仿真设置 \(H=30,T_o=1\)；真实平台设置 \(H=46,T_o=1\)，预测45个未来动作步，在30 fps下覆盖1.5秒。
  • 边缘部署：摘要报告 RDK S600 与 RDK S100 的 INT16 结果；所给正文还称在 RTX 4090 和三种边缘设备上测试，但节选未提供第三种边缘设备及其完整数值。
AI导读和推荐理由
  • 推荐这篇的核心原因不是它提出了更大的通用 VLA，而是它把多视角策略的部署瓶颈拆成视觉编码、条件长度和动作采样三个部分，并在同一架构内联合优化。
  • 对 π 系列研究而言，它提供了一个值得独立验证的假设：边缘端实时性未必只能依靠动作专家量化或减少生成步数，先压缩跨视角视觉条件也可能带来更直接的收益。

与π系列的关系

  • RTPolicy与 π0、π0-FAST、π0.5 和 OpenPI 同属视觉条件机器人动作策略方向，但不是 π 系列模型，也不是 OpenPI 实现；原文没有表明其继承这些模型的权重、训练代码或动作表示。
  • 论文在 RoboTwin 2.0 主表中直接对比官方排行榜的 π0：RTPolicy 为 52.26%，π0 为 46.4%。这支持其在该单任务协议下的效果，但不是统一训练实现、参数规模和计算预算下的严格等成本比较。
  • 论文将 π0.5 作为多视角条件开销的动机之一，指出多视角输入会增加动作模型处理的视觉特征量；RTPolicy的应对方式是在动作生成前完成稠密跨视角融合，再把三视角的900个 token 压缩为12个。
  • 与 π0-FAST 的关系仅限于都关注动作生成效率；所给原文未报告对 π0-FAST 的直接实验，也没有验证 RTPolicy 的视觉压缩能否与 FAST 动作 token 化叠加。
  • OpenPI可以作为迁移与复现载体，但本文没有使用 OpenPI，也没有证明12-token视觉接口能直接替换 π0/π0.5 原有视觉条件而不损伤预训练语义能力。

对Austin研究的启发

  • 在 OpenPI 中增加一个可插拔的 multi-view compressor 接口：保持 π0/π0.5 主干和动作执行器不变，只替换视觉条件路径，分别测试冻结主干、仅训练压缩器，以及联合微调三种设置。
  • 建立“成功率—端到端延迟—新观测生效时间”三轴评测，而不只记录模型前向耗时；在异步执行器中记录每个观测对应的动作块版本，直接测量干扰发生后多少毫秒或多少控制步开始纠偏。
  • 对引导场 \(G\) 或其他条件遵循模块，可先在稠密多视角特征上注入空间约束，再压缩成少量 token；并增加条件违反率监控，判断池化是否抹掉小目标、禁入区或接触点信息。
  • 加入单相机缺失、时间戳错位、帧率不一致和相机外参扰动。若固定 view embedding 在这些设置下失效，可改为由相机内外参、时间戳和有效性 mask 共同生成视角条件。
  • 复现时应把“4步流生成”与“视觉压缩”分开消融：先固定动作生成器比较900/12 token，再固定视觉条件比较2/4/10步，避免把吞吐提升错误归因于单一模块。

一句话总结

RTPolicy由苏州大学、D-Robotics、同济大学上海自主智能无人系统科学中心及中国科学院自动化研究所团队提出，通过冻结DINOv3 ConvNeXt、将三视角900个视觉token压缩至12个并以4步流匹配DiT生成动作，在RoboTwin 2.0取得52.26%平均成功率、真实双臂平台取得72.0%，并在RDK S600 INT16上达到30.35 ms（32.9 Hz）。
