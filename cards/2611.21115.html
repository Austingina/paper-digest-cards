深读｜ReuseMem

📐 原版模型结构图详解🤖 向千问提问本篇论文原文 ↗

问题

  • 机器人常需利用已经离开视野的信息完成后续操作，但记录时往往还不知道未来请求：同一段经历可能分别用于识别容器中的物体、找回物体原位置，或判断事件先后顺序。
  • 现有记忆增强策略通常证明“不同任务可使用各自历史”，却未充分回答“同一份预先记录、在不覆盖原记忆的情况下，能否支持多个需要不同证据的后续目标”。
  • 历史事实与当前动作之间存在错位：记忆可以说明目标物体是谁、原来在哪里，却不能直接给出物体移动后应从哪里抓取；前一请求还会改变后续请求的当前场景。
  • 本文在仿真与 SO101 真机桌面场景中，将基于 π0.5 的预训练策略骨干冻结，仅学习记忆检索与轻量动作接口；执行是结合当前观测、近期执行历史和长期记忆反复生成动作的闭环过程。
  • 作者目标是让一份与未来目标无关的视觉记录可被多个后续操作请求复用，同时提高多目标联合完成率，并控制长期记录的存储与推理开销。

方法

  • 输入与调度（Input/Dispatch）：左图将一次“指令至首条命令”的响应拆分为串行阶段；请求首先解析当前指令/目标，并完成输入封装与任务分派，随后把当前观测特征及目标上下文送入记忆处理链路。
  • 记忆处理（Memory Processing）：该阶段包含 MemER 的高层视觉语言模型（High-level VLM），负责根据目标检索并整合历史证据。观测被编码为 $A_i\in\mathbb R^{16\times1024}$，由原型引用重建 $\widehat V_i=\bar A_{p_i}+T_i$，再计算因果检索键 $k_i=E_\phi(\widehat V_{\le i},\eta_{\le i})\in\mathbb R^{256}$。
  • 动作策略计算（Action-policy Computation）：检索到的互补记忆与当前场景特征融合后输入动作策略；策略以当前目标、视觉证据和时序上下文为条件，生成首条可执行机器人命令，完成从 instruction 到 first command 的端到端响应。
  • 调用内记忆缓存（Within-call Memory-K/V Caching）：右图比较持续目标（continuing-goal）调用在启用与未启用缓存时的耗时。复用高层模型中已计算的 memory Key/Value 张量，避免重复编码相同历史上下文，使后续调用的平均响应时间降低 $9\,\mathrm{ms}$。

  • 整体流程为：目标无关的 Writer 记录视觉经历并建立公共记忆库 → Reader 根据后来给出的语言请求检索互补历史证据 → 融合模块将证据、近期执行观测、当前图像和机器人状态组合 → 冻结的预训练策略通过低秩调制生成动作。
  • Writer 对每个观测提取视觉特征；只有同时满足池化余弦相似度和逐 token 最大距离约束时，才复用已有外观原型。相似外观只存一次，但每次出现仍保留独立的帧号、元数据、有效位、原型引用和因果检索键，因此压缩外观而不丢失事件顺序。
  • Reader 先搜索候选锚点，再选择参考帧及其时间相关支持帧，并加入均匀覆盖帧；经稳定去重和时间填充后，向动作策略提供固定数量的历史槽位。所有目标读取同一份录制期记忆，执行期观测不会覆写它。
  • Reader 不以人工标注的“关键帧”为监督，而是比较多个候选记忆选择在同一目标、不同当前状态下对专家动作预测损失的影响；损失更低的选择获得更高偏好。Reader 更新后重新执行贪心检索，再用部署时相同的选择规则训练动作接口。
  • 动作侧显式区分“过去提供的事实”和“当前场景中的可操作位置”：检索历史与近期执行观测先通过当前场景和机器人状态进行残差融合，当前帧原生视觉 token 则直接进入策略。
  • 相对匹配基线，ReuseMem 不改动 π0.5 骨干及其原生注意力，只训练 Reader、宽度较小的融合残差和动作专家中的低秩调制增量；离散检索不接收动作损失的端到端梯度。
  • 为降低动作采样开销，每次策略调用只计算一次固定记忆的各层 key/value；去噪过程中重新计算动作 query 和注意力，而新观测或新指令到来时才重建记忆投影。

实验与结果

  • 四个仿真任务共评测 400 次独立目标执行和 200 个双请求连续序列。ReuseMem 的单目标成功率为 74.5%（298/400），高于 Uniform-Memory 的 54.0%（216/400）、MemER 的 39.3%、MME-VLA 的 32.5%和 No-Memory 的 25.3%。
  • 在最直接衡量“一份记忆服务多个目标”的 All-goal 指标上，ReuseMem 完成 121/200 份公共记录对应的两个独立目标，即 60.5%；匹配动作适配方式和历史槽位预算的 Uniform-Memory 为 72/200，即 36.0%，绝对提升 24.5 个百分点。
  • 不重置场景的双请求 Sequence 成功率为 58.0%（116/200），Uniform-Memory 为 35.0%（70/200），绝对提升 23.0 个百分点。这说明检索到的历史证据在前一操作改变场景后仍可与新的当前观测结合。
  • 其余完整配置的 All-goal / Sequence 结果分别为：No-Memory 5.5% / 7.5%，MME-VLA 14.5% / 11.5%，MemER 20.0% / 20.5%。但这些外部系统沿用各自原生记忆和策略接口，不能视为只改变检索模块的严格控制实验。
  • ReuseMem 在四类历史线索上均改善联合目标完成率，但隐藏物体交换任务仍最难：其 All-goal 成功率仅 30%，而其他任务为 64%–80%；作者将困难归因于遮挡和交换过程中目标身份的持续维护。
  • 原文提供了“去除检索学习”“仅单一当前状态监督”“去除当前融合”等消融设计，也称进行了记忆干预、存储及响应时间测量；但所给论文正文截断于消融结果开头，未包含这些实验的具体数字。两个真机场景的定量结果同样未出现在所给片段中，不能据此补报。

局限与可以继续做的

  • 证据范围有限：主要量化结果来自四个仿真任务，每项仅有 50 份测试记录，且都围绕一份历史对应两个后续目标；尚不能证明方法可扩展到更长时间跨度、更大记忆库或更多连续请求。
  • 仿真中的隐藏物体交换仍只有 30% All-goal 成功率，说明外观记忆与检索尚不足以稳定处理遮挡、身份交换和持续目标绑定；这也是 Austin 项目“策略是否持续跟随目标”的相邻失败模式。
  • ReuseMem 表达的是历史视觉证据，而不是物体期望变化的 G 或 A/F 交互几何；它能帮助回答“过去发生了什么、目标原来在哪里”，但不能凭检索本身创造未学过的接触方式，也未直接约束动作方向或放置轨迹。
  • 基线解释需谨慎：与 Uniform-Memory 的比较匹配了底层策略、专家数据和动作训练预算，最能隔离学习检索的作用；MME-VLA 和 MemER 则是完整外部配置，性能差异同时包含策略与接口差异。
  • 可继续做的实验是把每份记录扩展为同一初始场景下的“物体 × 目标 × 请求顺序”交叉设计，专门留出未见组合；分别报告首个目标、后续目标、失败恢复以及连续多请求成功率，检验收益是否来自真正的证据复用而非熟悉关联。
  • 还可在 ReuseMem 的历史槽位上叠加 A/F 或 G 条件，进行记忆置乱、关键帧替换、G 置零/反向/交换等干预；由此区分“找对了历史证据”“理解了目标变化方向”和“当前闭环执行正确”三个环节。
实验设置
  • 仿真平台：RoboMME 派生的四项任务，分别考察事件相对放置、时间顺序、隐藏物体身份和短暂视觉提示。
  • 仿真数据：每项任务含 100 份训练记录、20 份验证记录和 50 份测试记录；每份公共记录对应两个后续目标。
  • 仿真评测：每种方法共 400 次独立目标执行；All-goal 在相同录制后世界状态和记忆上恢复分支，要求两个独立请求均成功；Sequence 不重置场景，要求连续完成两个请求，共评测 200 份双请求序列。
  • 真机平台：SO101 桌面操作；两个场景各有 50 条训练演示、10 条验证演示和 20 条测试记录，每份记录对应三个后续请求，并分别评估独立请求、三目标联合成功和连续三请求序列。
  • 仿真基础策略：RoboMME 的 FrameSamp+Modul MME-VLA，建立在 π0.5 上；SO101 使用机器人专属的预备策略。
  • 冻结与训练：基础策略、原生注意力和视觉编码冻结；学习 Reader、因果检索键编码器、当前场景融合及 18 层中的 rank-8 调制增量。
  • 记忆输入：Reader 搜索 8 个候选锚点、选择 4 个参考观测，每个参考观测选取 3 个支持观测，并加入 8 个均匀覆盖观测；去重和填充后输出 24 个历史槽位。
  • 动作输入：24 个检索历史观测、7 个严格早于当前时刻的执行观测及当前观测；每个观测贡献 16 个视觉 token，总计 512 个、宽度为 1024 的 token。
  • 视觉记忆：单帧外观特征尺寸为 \(16\times1024\)，检索键维度为 256；历史/近期特征使用 width-32 残差模块与当前上下文融合。
  • 优化：Reader 与动作接口使用 AdamW，最多训练 20,000 步，并按验证集表现选择检查点。
  • 对照：No-Memory 只接收当前输入；Uniform-Memory 从相同记忆库均匀选择 24 个历史观测并采用匹配的动作适配；另比较发布版 MME-VLA 和 RoboMME 中复现的 MemER。
  • 所给正文未披露外观原型共享阈值、逐 token 距离上限、Reader 温度、偏好间隔、学习率及完整 batch 组成的具体数值，相关细节被指向附录。
AI导读和推荐理由
  • 推荐这篇的核心原因不是“又一个长时记忆模块”，而是它把同一份录制同时配给多个后续目标，并用不同当前状态下的动作效用监督检索，提供了可操作的组合数据与闭环评测范式。
  • 对 OpenPI 路线也有直接参考价值：它没有重训 π0.5 骨干，而是用外接 Reader、当前场景融合和低秩调制接入冻结策略，并以严格匹配的 Uniform-Memory 隔离学习检索的收益。

与本项目关系

  • 与 Austin 项目最强的联系在组合数据设计和 OpenPI 执行器：ReuseMem 为同一段历史配置多个目标及不同当前状态，并把检索结果接入基于 π0.5 的冻结策略，适合作为“同一场景、多目标”和未见组合评测的具体参照。
  • 两者的条件表示并不相同。ReuseMem 选择的是能够回答身份、原位置或事件顺序的历史视觉证据；G / A-F 表达的是“接近哪个交互区域、物体应如何变化”的运动几何。因此它不能直接证明策略会持续遵循 G，也不能替代接触、放置和目标运动方向的条件。
  • 本文的 Sequence 指标覆盖了前一操作改变场景后的后续执行，与项目中的放置、失败恢复和目标持续跟随问题有关；但现有协议主要验证历史事实能否被再次利用，并未报告 G 置零、反向或交换式的几何条件遵循测试。
  • Reader 在同一目标的多个当前状态上比较候选证据，比只对单帧做相关性检索更接近闭环需求；不过它仍可能利用熟悉的物体—目标关联。要证明组合泛化，还需明确留出未见的物体 × 目标 × 场景组合。

启发

  • 将 LIBERO 或自建数据按“公共观察历史 → 多个后续语言目标 → 每个目标的多个当前状态”重组；训练/测试按物体 × 目标 × 场景划分，并增加“同一初始场景、不同目标”的成对样本，避免把任务识别误当成组合能力。
  • 在 π0/π0.5 执行器上建立三组匹配对照：均匀历史 + G、学习检索 + G、学习检索 + A/F；冻结同一骨干并匹配 LoRA、训练步数和视觉 token 预算，以区分历史选择、几何表示和动作适配各自的贡献。
  • 把 ReuseMem 式“候选条件对专家动作预测是否有帮助”改造成 G 条件效用监督：对同一当前状态构造正确 G、置零 G、反向 G、交换目标 G，并比较动作预测和闭环轨迹差异；若只改变任务类别而未持续改变物体运动方向，应判为未真正遵循条件。
  • 将评测拆成检索、意图和执行三级：先验证是否找对目标物体及历史证据，再验证预测的 G/A-F 是否指向正确交互区域和物体变化，最后报告抓取、送达、放置、失败恢复及连续请求成功率。
  • 针对“抓到了但没送到正确目标”，在连续序列中保存不可覆写的公共历史，同时记录独立近期执行历史；分别干预两者，检查错误来自原始目标证据丢失、当前目标跟踪漂移，还是策略缺少放置技能。
  • 复现论文的记忆干预思想时，可交换两个目标的检索槽位、删除身份帧或原位置帧，并与 G 反向/交换联合测试；这比单纯观察成功率更能确认策略究竟依赖历史证据、语言捷径还是几何条件。

一句话总结

ReuseMem 由 Chung-Ang University 提出，通过动作预测效用训练 Reader，从一份目标无关记忆中为多个请求选择历史证据并接入冻结的 π0.5 策略，在四个仿真任务上取得 60.5% 的双目标 All-goal 成功率，较匹配的均匀记忆提高 24.5 个百分点。
