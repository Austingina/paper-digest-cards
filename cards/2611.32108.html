深读｜Duo

📐 原版模型结构图详解🤖 向 AI 提问本篇论文原文 ↗

问题

  • 双臂操作不仅要求两只机械臂分别产生合理动作，还要求它们在空间上对齐、在时间上衔接；递交、翻转包裹和折叠纸箱等任务中，一只手臂的正确动作取决于另一只手臂的位置与执行进度。
  • 常见流式双臂策略把同一未来时刻的左右臂完整动作合并为一个 token：注意力能够区分时间步，却不能把左右臂作为独立空间单元显式交互。另一类方法使用双分支、双骨干或额外协调模块，但会增加参数量和架构复杂度。
  • 论文同时覆盖仿真与真机，研究对象包括 VLA 和 WAM；Duo 改造并重新训练策略动作头，而非冻结现有策略后外挂推理模块。原文未明确披露预训练 VLM 骨干是否冻结，也未将执行协议明确表述为开环或闭环。
  • 作者目标是在不引入独立双臂分支或额外协调模块的前提下，以一个共享流匹配动作头提升双臂策略的时空协调能力，并兼顾成功率、计算效率和跨模型可扩展性。

方法

  • 统一动作策略（Combined Action Policy）：在每个未来时刻 $h$，先拼接左右臂噪声动作 $[X_{\tau,h}^L;X_{\tau,h}^R]\in\mathbb{R}^{2d}$，再投影为单个共享 token；两臂信息在进入注意力层前即被混合，并由共享动作头联合输出双臂动作。
  • 分离动作策略（Separate Action Policy）：左右臂分别使用 arm-specific tokens 与独立动作头，各自接收初始状态 $s^L,s^R$ 并预测 $X^L,X^R\in\mathbb{R}^{H\times d}$。该设计保留手臂身份，但两条生成路径缺少显式跨臂交互，难以建模同步与协作约束。
  • Duo 手臂级标记（Arm-wise Action Tokens）：对手臂 $a\in\{L,R\}$，构造状态 token $S^a=E_s^a(s^a)+e^a$ 和动作 token $A_h^a=E_x^a(X_{\tau,h}^a)+e^a$；两臂共形成 $2(H+1)$ 个 token，且 $A_h^L,A_h^R$ 共享时间位置 $h$。
  • 联合动作生成（Joint Action Generation）：Duo 将上述 token 输入同一共享动作头，通过 cross-arm self-attention 在保持手臂身份的同时交换双臂信息；解码 $A_h^{\prime L},A_h^{\prime R}$ 得到联合流场 $v_\theta(X_\tau,\tau;c,s^L,s^R)\in\mathbb{R}^{H\times2d}$，最终生成动作块 $X=[X^L\;X^R]$。

Comparison of bimanual action generation designs. Combined action policies combine both arms' actions in each token and use a shared head. Separate action policies use arm-specific tokens and independent heads. Duo retains arm-specific tokens while jointly generating both arms' actions through cross-arm self-attention in one shared head.
  • 整体流程为：相机图像与语言指令经预训练 VLM 骨干编码为上下文；左右臂状态及带噪未来动作分别投影成 arm-specific token；共享动作头联合处理全部 token；输出被解码为流场并迭代更新噪声，最终同时生成两臂的动作块。
  • 对每只手臂，Duo 使用一个状态 token 和每个未来时间步一个动作 token，并加入可学习的手臂身份嵌入；两臂在相同未来时刻共享时间位置索引，但保留独立 token。
  • 左右臂 token 被拼成长度为 \(2(H+1)\) 的单一序列，在同一个动作头内执行自注意力。因此，每只手臂的预测可以直接关注另一只手臂的当前状态及整段候选未来动作。
  • Duo 使用 rectified flow 训练：两臂共享同一个流时间 \(\tau\)，模型学习从高斯噪声到示范动作块的速度场；推理时经过 \(N\) 次流积分，每一步都重新计算跨臂注意力并联合修正两条轨迹。
  • 相对 combined-action 基线，Duo只改变动作头中的双臂表示与投影方式，不更换其 VLM/WAM 主体，也不增加独立协调网络；相对 separate-action 方法，它保留 arm-specific token，但仍由一个共享动作头联合生成两臂动作。
  • 论文还比较了动作维度的不同分组粒度：更细粒度 tokenization 仅带来边际收益，按物理手臂分组则以更低计算量保留了几乎全部提升。

实验与结果

  • RoboTwin 2.0 上，Duo 对全部四个被改造的基线均提高总体成功率：SmolVLA 从 22.31% 升至 24.91%（+2.60 个百分点），Lila-WAM 从 32.91% 升至 34.01%（+1.10），FLOWER 从 50.15% 升至 62.70%（+12.55），\(\pi_{0.5}\) 从 58.35% 升至 67.37%（+9.02）。其中 \(\pi_{0.5}\)-Duo 的总体、Clean 和 Random 成功率分别为 67.37%、80.36% 和 54.38%，均为表中最高。
  • FLOWER-Duo 的 Random 成功率由 31.62% 提升至 46.66%（+15.04 个百分点）；但 SmolVLA-Duo 和 Lila-WAM-Duo 的 Random 结果分别仅为 3.74% 和 4.90%，后者还下降 2.00 个百分点，说明动作协调设计不能弥补基础模型近乎失效的 OOD 感知或泛化能力。
  • 按双臂运动模式划分后，FLOWER-Duo 在“两臂同时运动”任务上的 Clean、Random 增益分别为 14.3 和 16.5 个百分点；在“两臂依次运动”的 Random 设置中，它比 \(\pi_{0.5}\) 高 13.7 个百分点，收益主要集中在确实需要并发或顺序协调的任务。
  • RoboDojo 上，FLOWER-Duo 的官方 Score/SR 为 7.07/3.75%，高于原始 FLOWER 的 4.89/1.63%，但仍低于 \(\pi_{0.5}\) 的 11.41/6.91%。它取得表中最高的随机泛化、精度和记忆分数，分别为 2.27、12.88 和 5.52；不能据此称其总体性能最佳，因为总体 Score、SR、标准泛化、长程和开放任务指标均非第一。
  • 真机三项任务中，FLOWER-Duo 的成功率分别为 90.0%（软包裹）、83.8%（硬包裹）和 40.0%（装箱），对应 \(\pi_{0.5}\) 为 73.8%、72.5% 和 20.0%；成功试验平均完成时间也分别由 25.5/34.8/28.8 秒降至 22.7/33.1/27.1 秒。定性案例中，\(\pi_{0.5}\) 分别出现翻转失败和稳定纸箱时将其掀翻，而 FLOWER-Duo 完成了相应任务。
  • 硬包裹任务的数据扩展实验覆盖 2–32 小时示范：小数据量下 \(\pi_{0.5}\) 领先，8 小时时两者持平，FLOWER-Duo 在 16 和 32 小时时反超且未表现出饱和。所给正文没有披露图中各数据点的精确成功率与时间，因而无法进一步列出可核对数值。
  • 消融结论显示，测试时屏蔽跨臂注意力会显著降低成功率，支持收益来自跨臂交互而不只是 token 数量变化；按手臂分组相较更细粒度方案以低 6.12 倍的计算量保留几乎全部增益。所给原文在消融章节开头截断，未提供该实验的完整表格、绝对成功率及计算量定义。

局限与可以继续做的

  • Duo 改善的是动作表示与协调，不能替代视觉 OOD 泛化：SmolVLA 和 Lila-WAM 在 RoboTwin Random 场景中的基础成功率很低，加入 Duo 后仍接近失效，且 Lila-WAM-Duo 的 Random 成功率出现下降。
  • RoboDojo 仍极具挑战，所有策略总体成功率都低于 7%；FLOWER-Duo 虽在精度、记忆和随机泛化子项领先，但开放任务分数由 FLOWER 的 1.50 降至 0.25，也未超过 \(\pi_{0.5}\) 的总体 Score 与 SR。现有证据不足以支持“所有能力维度都受益”或“通用性能最佳”。
  • 真机只使用一种 AgileX Piper X 双臂平台和三项任务；正文未给出每个条件的试验次数、随机种子、置信区间或显著性检验。成功率和速度优势是否能外推到不同形态、控制频率、相机布局和高接触力任务，仍需验证。
  • 可在 OpenPI 中实现可切换的 combined/arm-wise token 接口，在保持视觉语言骨干、数据、动作块长度和流积分步数一致的条件下，分别比较完整跨臂注意力、单向注意力、动态掩码和完全隔离注意力，报告成功率、延迟、显存及轨迹碰撞率。
  • 可增加在线协调监控：记录左右臂注意力、末端间距、接触时序、等待时间和纠正动作数，并按“单臂／同时运动／依次运动”分桶评测，以判断成功率提升究竟来自空间避碰、递交时序，还是更平滑的动作生成。
  • 对引导场 \(G\) 或任务约束条件的后续实验，可分别测量两臂 token 对语言条件、几何约束和另一臂候选轨迹的敏感性；同时加入遮挡、时间延迟、单臂卡滞和状态噪声，检查联合生成是否会导致错误在两臂之间传播。
实验设置
  • RoboTwin 2.0：仿真 Aloha-AgileX 双臂机器人，50 项任务；每项任务使用 50 条 clean 示范，共 2,500 条，训练一个多任务策略。
  • RoboTwin 2.0 评测：Clean 与训练域一致；Random 加入桌面杂物、随机背景与光照、桌高扰动；分别报告两种设置的成功率，并以二者均值作为 Overall。
  • RoboTwin 2.0 基线：combined-action 策略 SmolVLA、FLOWER、\(\pi_{0.5}\)、StarVLA，WAM 策略 Lila-WAM、Fast-WAM，以及 separate-action 策略 TwinVLA、InterACT。
  • Duo 实际集成到 SmolVLA（0.45B）、Lila-WAM（0.50B）、FLOWER（0.89B）和 \(\pi_{0.5}\)（3.62B）；受算力限制，StarVLA（4.50B）和 Fast-WAM（6.00B）只作为参考基线，未给出 Duo 版本。
  • RoboDojo：仿真双臂 ARX X5，42 项任务；使用官方 35 项任务、3,500 条示范训练；42 项任务各评测 50 个 episode、一个随机种子，共 2,100 个 episode。
  • RoboDojo 指标：官方 Score、总体成功率，以及标准泛化、随机泛化、精度、长程执行、记忆和开放任务六项能力分数。
  • 真机：AgileX Piper X 双臂机器人；任务为软包裹处理、硬包裹处理和装箱；比较 FLOWER-Duo 与 \(\pi_{0.5}\)，报告成功率及成功试验的平均完成时间，包裹任务另区分 ID 与 OOD。
  • 硬包裹数据扩展实验使用 2、8、16、32 小时训练数据；人类示范平均时长为 18.3 秒，由真实机器人训练集随机抽取 20 条示范计算。
  • 动作生成采用 rectified flow；输入动作块长度 \(H\)，推理积分步数 \(N\)。所给正文未披露 \(H\)、\(N\)、控制频率、优化器、学习率、训练硬件、真实任务试验次数，以及预训练骨干是否冻结。
AI导读和推荐理由
  • 推荐这篇的核心原因不是它提出了新的大规模 VLA 骨干，而是它识别出双臂流式策略中一个可迁移的表示瓶颈：把左右臂合并进同一时间 token，会隐藏“哪只手臂在做什么”的空间结构。
  • 论文同时在四种 0.45B–3.62B 的 VLA/WAM、两个仿真基准和真机任务上验证这一设计，并明确展示收益边界：强基础策略可获得明显协调增益，但低 OOD 能力不会因动作 token 重组自动修复。

与π系列的关系

  • Duo 不是 \(\pi\) 系列的新基础模型，而是可嵌入流匹配双臂策略动作头的表示设计。论文直接改造 \(\pi_{0.5}\)，把同一未来时刻的完整双臂动作 token 拆成左右臂 token，并允许它们在共享动作头内通过自注意力交互。
  • 对 \(\pi_{0.5}\) 而言，变化集中在状态与动作的 arm-wise 编码、手臂身份嵌入和动作头 token 序列；论文没有声称更换其 VLM 骨干、引入双分支骨干或额外协调器，也未披露预训练骨干是否冻结。
  • 论文在相关工作中将 \(\pi_0\) 和 SmolVLA 归为“每个时间步把完整动作向量嵌入一个 token”的连续策略，但实验只报告了 \(\pi_{0.5}\)-Duo，没有给出 \(\pi_0\)-Duo 结果。
  • Duo 与 FAST/\(\pi_0\)-FAST 的关系是互补而非等同：FAST关注跨动作维度与时间的离散压缩，Duo关注连续流式动作头中按物理手臂划分 token 并建立跨臂注意力。所给原文没有报告与 \(\pi_0\)-FAST 的直接对照或组合实验。
  • OpenPI 是工程实现框架，Duo 是动作表示与注意力设计；论文未说明代码基于 OpenPI，也没有提供 OpenPI 集成、检查点或兼容性验证，因此不能把 \(\pi_{0.5}\)-Duo 直接视为已有 OpenPI 模型。

对Austin研究的启发

  • 在 OpenPI 执行器中把动作 tokenization 做成可配置接口：保留原 combined token 路径，增加 left/right arm token、共享时间位置编码、arm-ID embedding 和跨臂 attention mask，从而能在相同 checkpoint 初始化与训练预算下做严格配对实验。
  • 将“跨臂协调是否真的被使用”纳入评测：推理时依次屏蔽全部跨臂注意力、仅屏蔽左到右或右到左的信息流，并测试注意力延迟或错位；若成功率随任务角色和时序发生可解释变化，证据会比只比较最终均值更强。
  • 对引导场 \(G\) 的条件遵循，可将语言/几何约束 token 与双臂动作 token 分开记录，检查两只手臂是否同时满足约束；建议增加递交窗口误差、双臂同步误差、末端最小距离、共享物体姿态误差和动作修正次数，而不只报告任务成功率。
  • 闭环评测应按单臂、两臂并发、两臂依次动作分桶，并加入视觉 OOD 与控制故障两条独立轴。本文结果表明，Duo 对并发协调收益最大，但无法修复基础视觉策略在 Random 场景中的近乎完全失败。
  • 计算评测需同时报告 token 数、注意力 FLOPs、流积分总延迟和控制周期超时率；论文给出的 6.12 倍计算优势说明“以物理手臂作为交互单元”可能比逐关节或逐动作维度 tokenization 更适合作为实时系统默认方案。

一句话总结

上海交通大学、Quicrobot 等机构的作者提出 Duo，以共享流匹配动作头中的左右臂 token 和跨臂自注意力建模双臂时空协调，使 RoboTwin 2.0 上 FLOWER 与 \(\pi_{0.5}\) 的总体成功率分别提升 12.55 和 9.02 个百分点，并由 \(\pi_{0.5}\)-Duo 达到 67.37%。
