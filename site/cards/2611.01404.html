问题

  • 智能体机器人不再只调用动作策略：高层视觉—语言“脑模型”会持续观察、推理和选择工具，VLA 再把指令转换为动作块。共享集群因此同时面对两类约束——脑模型的长生命周期 KV cache 驻留，以及 VLA 动作块的实时截止期。
  • 现有机器人服务研究主要关注动作模型的 deadline、多模型执行和 GPU 共享；Agent 服务研究则关注工具调用间隙中的 KV 保留与缓存抖动。两者尚未共同回答：一个 GPU 集群究竟能稳定服务多少台持续运行的智能体机器人。
  • 论文研究的是仿真轨迹及其服务器回放，而非提出或训练新策略：任务来自 LIBERO-PRO，GPT-6-Astra 通过 RPent 调用感知、几何、脚本运动及 LIBERO 微调的 π0.5；脑服务则用 Qwen3.6-27B 代理并在真实 vLLM 引擎上回放。
  • 作者目标是建立可测量的双层容量模型，找出系统何时受 VLA 截止期限制、何时受脑模型 KV 工作集限制，并验证简单准入控制能否恢复持续机器人集群的吞吐。

方法

  • 机器人程序（Robot program）：左侧程序执行感知、工具调用与环境交互；在第 $i$ 轮形成上下文 token 序列 $C_i$，并依据工具决策分别触发脑服务或 $\pi_{0.5}$ VLA 服务，构成具有严格先后依赖的闭环请求流。
  • 脑服务（Brain serving）：上行“Context request”携带持续增长的前缀，满足 $C_{i-1}\prec C_i$；服务端复用前缀对应的 KV-cache，并生成长度为 $o_i$ 的“Tool decision”返回程序。实验以保持长度与精确前缀关系的随机 token 在 vLLM 上重放，Qwen3.6-27B 仅代理计算及缓存成本。
  • VLA 服务（VLA serving）：下行“VLA tool call”将视觉观测与任务指令送入 $\pi_{0.5}$，输出动作块 $A_t=(a_t,\ldots,a_{t+H-1})$，再以“Action result”回传。其采用 FCFS 批处理，每台机器人至多保留一个未完成请求，并可预取动作块以降低控制饥饿。
  • 独立 GPU 池与回放控制：Brain 与 VLA 位于分别剖析的 GPU 服务池；脑请求完成后等待原轨迹环境间隔 $\Delta t_i$ 再发下一轮。episode 边界的准入上限 $K$ 约束活跃程序数，从而抑制增长 KV 工作集引发的缓存抖动。

Context request / serving overview for brain and VLA workload in the paper.
  • 整体流程为：采集完整机器人程序轨迹 → 分别剖析 π0.5 动作层和脑模型服务成本 → 按原始上下文增长、输出长度及环境步间隔，在 vLLM 上重放依赖请求 → 测量截止期违约、缓存命中、请求吞吐和完整 episode 吞吐。
  • 对每个虚拟机器人保留其上一轮的精确 token 前缀，并按轨迹新增输入长度和输出长度发起下一轮请求；响应完成后，再等待原轨迹记录的环境步间隔，从而保留程序内部的依赖关系和调用节奏。
  • 回放不复现 GPT-6-Astra 的语义内容，而使用保持输入长度及精确前缀关系的随机 token ID；Qwen3.6-27B 只作为可控的计算与 KV-cache 成本代理。论文没有声称该代理复现 Astra 的输出质量。
  • VLA 层采用 FCFS 批处理服务器：机器人可预取动作块，但每台机器人最多保留一个未完成请求；动作缓冲为空的控制 tick 被记为 starvation，并以 starvation 不超过 1% 定义通过 SLO。
  • 脑服务同时考察持续负载和有限作业：持续回放中，机器人完成一个 episode 后立即补入新 episode；有限回放中，每台机器人执行两个 episode 后退出，用来区分短期拥塞与持续工作集抖动。
  • 准入机制不修改脑模型、π0.5 或 vLLM 的模型结构，而是在 episode 边界设置静态“活跃 episode”上限，限制同时占用 KV 工作集的机器人程序数量；未获准的 episode 在入口等待。

实验与结果

  • 80 个 LIBERO-PRO episode 共记录 1,862 次脑模型调用、216 次 VLA 工具入口和 1,582 个 VLA 推理块；74/80 个 episode 成功。脑调用次数是 VLA 工具入口的 8.62 倍，说明高层脑模型不是偶发规划器，而是持续参与控制。
  • 脑上下文中位数为 78.1k token、P90 为 131k，最大达到 214.7k；每轮新增输入中位数仅 3,279 token，而完整提示与新增输入之比中位数为 25.5 倍。若前缀被逐出，服务端可能为少量新增内容重新计算很长的历史。
  • GPT-6-Astra 单次请求时延中位数为 7.78 秒、P90 为 13.84 秒，而相邻脑调用之间的环境推进间隔中位数仅 1.00 秒；38.6% 的间隔甚至没有推进任何环境步。脑推理时间因此显著长于许多工具返回后的物理推进时间。
  • π0.5 在 batch 1 下的推理时延中位数为 160 ms。以五步动作块、1% starvation SLO 计，一张 H800 在 0.25 秒截止期下只能通过 1 台机器人，在 0.50 秒下可通过 8 台，在 1.00 秒下至少通过全部 32 台受测机器人；两张 GPU 在 0.50 秒下可通过 16 台。0.25 秒的双 GPU 实验只从 8 台开始，且该点已经失败，因而不能据此确定低于 8 台时的容量。
  • 对 Qwen3.6-27B，130k-token 前缀被逐出时，估算的 150-token 完整调用耗时为 6.78 秒；保留前缀时为 1.73 秒。215k 上下文的未命中 TTFT 为 10.26 秒，而保留前缀、仅追加约 3.3k token 时为 0.35 秒，显示 KV 驻留直接决定机器人程序的计算成本与等待时间。
  • 在持续脑服务回放中，并发从 20 台增加到 32 台后，吞吐由约 2.40 降至 0.60 请求/秒，提示词重算量升至约 150 万 token/分钟。设置静态活跃 episode 上限后，请求吞吐恢复至 2.24–2.25 请求/秒，完整轨迹程序吞吐由 1.30 提升至 5.00–5.55 episode/分钟。

局限与可以继续做的

  • 行为轨迹来自 GPT-6-Astra、RPent、π0.5 和 LIBERO-PRO 的特定组合；脑模型计算则由 Qwen3.6-27B 代理。随机 token 回放保留长度和前缀结构，但不保留真实语义、图像内容分布或不同 token 对注意力与生成行为的影响，结果不能直接外推到所有 VLM/VLA 系统。
  • 机器人部分是 LIBERO-PRO 仿真，不是真机闭环部署；VLA 容量实验还假定零网络 RTT、固定五步预取和连续需求。真实相机传输、控制总线、执行抖动、安全检查及异构机器人到达相位都可能降低 deadline-qualified capacity。
  • 论文只测试一类 H800 节点、一种脑模型代理和特定 vLLM 版本；π0.5 的容量数字也依赖五次去噪、五步动作块及 FCFS 批处理，不能当作 π0.5 或 OpenPI 在其他硬件上的固定容量。
  • 静态活跃 episode 上限证明了工作集准入的价值，但没有在所给正文中展示自适应阈值如何随上下文长度、剩余任务阶段、KV 块需求和动作紧急度动态变化。可进一步比较静态上限、按 KV 预算准入、基于复用距离的准入和 deadline-aware 联合调度。
  • 可执行的后续实验是把每台机器人的“动作余量、下一次脑调用时间、当前 KV 块数、前缀命中率”统一纳入调度器，并在真机或带网络抖动的硬件在环测试中绘制成功率—starvation—吞吐—GPU 成本的联合曲线，而不只报告服务吞吐。
实验设置
  • 仿真任务：LIBERO-PRO，共四个 suite；每个 suite 10 个任务、每个任务 2 个 seed，共 80 个 episode，其中成功 74 个。
  • 轨迹系统：GPT-6-Astra，low reasoning effort，经 Codex 在 RPent harness 中调用；工具包括渲染、几何推理、脚本运动和 LIBERO 微调的 π0.5。
  • 感知设置：采用 no-SAM3；一个小型配对检查中，含/不含 SAM3 的两组均为 19/20 成功。
  • 轨迹规模：1,862 条脑请求记录、1,782 个 episode 内调用间隔、216 次 VLA 工具入口和 1,582 个 VLA 推理块；日志按 response ID 去重。
  • 控制频率：20 Hz；π0.5 每个动作块为 5 步、执行 5 次去噪；评测动作块预算为 0.25、0.50 和 1.00 秒。
  • 硬件：8 张 H800 80 GB，NVLink 互连；脑模型实验使用 GPU 4–7。四 GPU all-reduce 实测总线带宽约 359 GB/s。
  • 脑模型代理：Qwen3.6-27B、BF16、TP=4；vLLM 0.17.1，开启 automatic prefix caching。
  • 软件环境：NVIDIA 驱动 535.161.08，nvidia-smi 报告 CUDA 12.3；PyTorch 2.10.0+cu128，用户态 CUDA 12.8。
  • KV cache：混合块大小为 784 token，观测到的缓存池分别为 4,270 和 4,396 块。
  • VLA 延迟测量：7 个 batch size，每个 shape 先预热 10 次，再测量 50 次并报告中位数。
  • VLA 容量协议：FCFS、五步预取、每台机器人最多一个 outstanding request、零网络 RTT；容量取两次重复实验都满足 starvation 不超过 1% 的最大已测机器人数量。
  • 单 GPU 测试机器人数量为 {1, 2, 4, 8, 16, 32}；双 GPU 为 {8, 16, 32}。
  • 持续回放：episode 完成后立即抽取新 episode；有限回放：每台虚拟机器人执行两个 episode 后结束。
  • 缓存抖动起点：首次出现完整前缀命中率低于 80% 的 120 秒窗口；没有出现该窗口的运行按右删失处理。
  • 完整 episode 只有在轨迹最后一次脑调用完成后才记为完成；未完成实例记为删失数据。
AI导读和推荐理由
  • 推荐这篇的原因不是它改进了 VLA 策略精度，而是它把 π0.5 放进“高层 VLM + 工具 harness + 动作策略”的真实服务链，揭示模型能力之外的部署瓶颈：动作 deadline 与长上下文 KV 驻留会在不同负载区间轮流限制机器人数量。
  • 对 π 系列日报而言，本文补足了训练与基准成功率之外的系统视角，并给出可以直接用于 OpenPI 服务端容量规划的指标：动作块 starvation、完整前缀命中率、重算 token 量、请求吞吐和完整 episode 吞吐。

与π系列的关系

  • 本文直接把 LIBERO 微调的 π0.5 作为 RPent 的 VLA 工具，并剖析其动作块延迟与多机器人容量；它不是 π0、π0-FAST 或 π0.5 的新架构，也没有提出新的 flow matching、动作 tokenizer、训练数据或损失函数。
  • 作者没有修改 π0.5 的策略权重，而是在模型外增加服务测量、FCFS 批处理、持续轨迹回放和 episode 级准入控制。核心贡献属于推理服务与系统调度，而非策略学习。
  • 所给原文没有报告与 π0、π0-FAST、OpenPI 执行器或其他 VLA 的同协议横向容量对比，也没有证明结论只对 π0.5 成立；更稳妥的理解是，π0.5 是被测动作层实例，长生命周期脑上下文才是论文新增刻画的工作负载。
  • 对 OpenPI 的直接启发是：仅优化单次 policy inference latency 不足以预测集群容量。动作块长度、预取深度、到达相位和脑模型 KV 工作集必须放在同一个闭环服务模型中评估。

对Austin研究的启发

  • 在 OpenPI 执行器旁增加可观测接口，逐机器人记录 action-buffer 剩余步数、请求排队时间、推理时延、starved tick、脑上下文长度、KV 命中率和 episode ID；否则无法判断失败来自策略本身还是服务层抖动。
  • 建立两维容量扫描：一维改变控制频率、动作块长度和预取深度，另一维改变活跃机器人数量及脑上下文规模；同时报告任务成功率与 1% starvation SLO，避免只用离线 GPU 吞吐推断闭环可用性。
  • 若系统包含引导场 \(G\) 或其他高层条件，应该专门测试 KV 逐出后重算、脑请求延迟突增和动作缓冲耗尽时的条件遵循：检查机器人是继续执行旧 chunk、进入安全保持，还是偏离 \(G\) 指令。
  • 可先复现静态 active-episode cap，再实现按预测 KV 块数和动作缓冲余量动态准入；优先保留“即将再次调用且动作余量较小”的上下文，并比较完整 episode/分钟、P99 脑延迟、starvation 与成功率。
  • “Austin”在所给论文中没有被定义，也没有证据表明作者与 Austin 或 OpenPI 团队存在直接合作；上述建议仅针对 π 系列/OpenPI 研究与部署场景。

一句话总结

华为的 Sida He 通过 80 个 LIBERO-PRO episode 证明，π0.5 机器人集群会在动作截止期与脑模型 KV 工作集之间切换瓶颈，而 episode 级准入可将持续回放的完整程序吞吐从 1.30 提升至 5.00–5.55 episode/分钟。
