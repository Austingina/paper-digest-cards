深读｜Co²Gen

📐 原版模型结构图详解🤖 向千问提问本篇论文原文 ↗

问题

  • 背景痛点：现有 VLA 模型（如 π0, OpenPI）主要在单臂非协作数据上预训练，即使经过单臂任务微调，在去中心化多机协作中仍因缺乏“基于对端状态的条件执行”能力而失败（例如右臂未等左臂开柜就尝试放物）。
  • 现有缺口：收集高质量的多机协作示教数据成本极高，需要双遥操作或复杂的同步接口；且现有 VLA 多机工作（如 InterAct, TwinVLA）多依赖双臂间的显式信息交互（Cross-Attention），未探索完全去中心化、仅通过环境状态隐式协调的场景。
  • 目标设定：提出 Co²Gen，一种无需人工遥操作、自动生成多机协作示教数据的框架。旨在证明用该数据微调的 VLA 在去中心化协作任务上能匹配人工遥操作数据的表现，并具备零样本人机协作能力。

方法

  • 多模态任务与场景输入（左上）：系统接收自然语言任务指令（如“将黄色方块堆叠在中央区域的绿色方块上”）与双臂工作台顶视环境图像观测，作为协作规划的初始上下文。
  • 基于MCTS的去中心化协作规划（中上）：两个基于大语言/视觉语言模型（LLM/VLM）的智能体分别扮演 Actor（提议子任务序列）与 Critic（从进度、分工合理性与前置条件三维度打分），结合预定义底层机器人技能库（Robot Skills）开展蒙特卡洛树搜索（MCTS），迭代搜索最优双臂协同调度方案。
  • Python协作计划代码生成（右上）：规划器输出可执行的 Pythonic 协作计划（Collaborative Execution Plan），在代码逻辑中显式嵌入 check_precondition(...) 环境视觉前置条件查询与角色分支控制（如 if arm == "right"）以调用 execute_skill(...)，实现无显式通信的隐式状态同步。
  • 闭环物理执行与数据收集（底部）：双机械臂在真实桌面环境中闭环执行该计划完成协同堆叠，经人工验证器筛选的成功轨迹存入数据集 $\mathcal{D}_{\text{task}}$ 并按机器人角色拆分以微调去中心化 VLA 策略。

The system diagram for our proposed collaborative plan generation approach.
  • 整体 Pipeline：输入自然语言任务与环境状态 → 去中心化协作规划（生成可执行 Python 函数）→ 自动执行与人类验证器筛选 → 生成分布式示教数据 → 分别微调各机器人的 VLA。
  • 去中心化协作规划 (Co²Gen)：
  • 形式：将协作计划表示为可执行的 Pythonic 函数，包含子任务调度、分配及基于环境反馈的前置条件检查（Pre-condition Check）。
  • 生成机制：采用协作蒙特卡洛树搜索 (Collaborative MCTS)。两个 VLM Agent 分别扮演 Actor（提议计划）和 Critic（评估打分），通过 UCT 策略迭代优化计划树。
  • 评分标准：Critic 从进度、任务分配合理性、前置条件检查三个维度打分（1-5分，总分15）。
  • 执行与数据生成：
  • 感知与控制：使用 VLM 查询环境前置条件（如“柜子是否打开”）；底层通过 Blob Detection + YOLOv8 获取粗坐标，IK 求解器生成轨迹，腕部相机精调抓取。
  • 人类验证器：引入人类作为任务成功与否的验证者，剔除执行失败的轨迹，避免 VLM 幻觉导致的错误数据污染训练集。
  • VLA 微调策略：
  • 去中心化训练：将协作数据集 $\mathcal{D}_{task}$ 按角色拆分为各机器人的局部数据流（包含自身关节状态、腕部相机及共享的顶部相机），分别独立微调 VLA。
  • 混合数据增强：提出 $VLA_{Co^2Gen+SA}$，将生成的协作数据与单臂人类示教数据混合，以兼顾轨迹多样性与协作协调性。

实验与结果

  • 主要结论：在去中心化协作任务（堆叠、存储）中，使用 Co²Gen 生成数据微调的 VLA ($VLA_{Co^2Gen}$) 表现显著优于仅用单臂数据微调的基线，且能匹配甚至超越基于人工遥操作协作数据微调的效果。
  • 零样本泛化：经过 Co²Gen 数据训练的 VLA 在零样本人机协作（HRC）任务中也能保持较高的成功率，证明其学到了通用的协调行为而非过拟合于特定机器人伙伴。
  • 消融对比：混合单臂人类数据的版本 ($VLA_{Co^2Gen+SA}$) 相比纯生成数据版本，在轨迹多样性和鲁棒性上通常表现更优（具体数值需参考原文表格，但趋势为混合数据提升稳定性）。
  • 失败模式分析：未训练协作数据的 VLA 常因忽略对端状态（如对方手臂未移开就进入工作区）导致碰撞或任务停滞；Co²Gen 生成的计划通过显式的 check_precondition 语句有效缓解了此类时序错误。

局限与可以继续做的

  • 依赖人类验证器：数据生成闭环中仍需人类判断任务成功，未能实现完全无人化的自动数据飞轮（尽管比双遥操作成本低）。
  • 规划器开销与实时性：MCTS 搜索和 VLM 前置条件检查在推理时可能引入延迟，虽然主要用于离线数据生成，但若用于在线重规划则效率较低。
  • 感知模块的局限性：底层控制依赖 Blob/YOLO + IK，对遮挡、动态物体或复杂接触状态的鲁棒性不如端到端 VLA 直接输出动作，限制了生成的示教数据的上限。
  • 可扩展性验证不足：目前仅在双臂（N=2）SO-101 低成本机械臂上验证，未测试异构机器人（如移动底盘+机械臂）或更多数量机器人的协作场景。
实验设置
  • 硬件平台：两台 SO-101 低成本机械臂，配备顶部 Zed2 双目相机和腕部相机。
  • 模型选择：
  • 规划/验证 VLM：GPT-5.6 (gpt-5.6-sol)。
  • VLA 策略：SmolVLA (smolvla_base)，轻量级开源 VLA。
  • 任务定义：
  • 协作存储：一臂开柜，另一臂放物入柜并关柜。
  • 协作堆叠：两臂分别抓取方块，在中心区域完成堆叠。
  • 数据与训练：
  • 每个任务收集 50 个成功示教 episode。
  • VLA 微调步数：20,000 steps。
  • 使用 DAgger 算法收集纠正数据以提升可靠性。
  • 评测协议：去中心化执行，两个 VLA 独立运行不共享内部状态，仅通过环境交互协调；每任务 20 次试验，记录成功率及子任务得分（最大14分）。
AI导读和推荐理由

与π系列的关系

  • 非直接竞争/互补：本文未直接使用 π0 或 OpenPI，而是使用 SmolVLA。但其核心思想——“通过高层规划生成结构化示教数据来弥补 VLA 在特定行为（如协作）上的缺失”——与 π0.5 中利用高层语义推理辅助低层控制的思路有异曲同工之妙。
  • 去中心化 vs 集中式：π 系列通常假设单一智能体或紧密耦合的双臂系统，而 Co²Gen 强调完全去中心化（Decentralized），各 VLA 仅通过环境状态隐式协调。这为 π 系列在多机场景下的部署提供了数据生成的新思路：即不修改模型架构（不加 Cross-Attention），而是通过数据分布的改变来涌现协调能力。

对Austin研究的启发

  • 数据合成管线借鉴：Austin 若需扩展多机协作或复杂时序任务，可参考 Co²Gen 的 “VLM 生成 Python 计划 -> 仿真/真机执行 -> 人类/自动验证 -> 微调 VLA” 闭环。特别是利用 LLM/VLM 生成带有 if-else 前置条件检查的代码作为“教师策略”，能有效解决 VLA 在长时序依赖上的弱点。
  • 混合数据训练：Austin 可尝试将 OpenPI 执行器生成的合成轨迹与少量真实遥操作数据混合（类似 $VLA_{Co^2Gen+SA}$），以平衡分布偏移和任务多样性。
  • 监控指标设计：在评测中引入“前置条件满足率”或“时序冲突检测”，而不仅仅看最终成功率，有助于定位 VLA 是感知错误还是协调逻辑缺失。

一句话总结

Co²Gen 通过去中心化 MCTS 生成带前置条件检查的可执行协作计划，自动构建示教数据微调 SmolVLA，实现了无需双遥操作即可匹配人工数据的去中心化多机及零样本人机协作能力。
