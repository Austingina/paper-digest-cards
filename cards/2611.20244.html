深读｜Right Goal, Wrong Body

📐 原版模型结构图详解🤖 向千问提问本篇论文原文 ↗

问题

  • VLA 默认训练时的动作指令与机器人实际运动之间关系保持不变；部署后若发生执行器重装、动作坐标系旋转、控制器增益变化、机械磨损或指令延迟，同一动作可能产生不同运动。此时模型可能仍找对目标，却出现过冲、误碰、物体移位或速度越界。
  • 重新训练或微调通常需要任务演示、额外计算和模型权重；已有快速适应、元学习及测试时策略塑形方法又往往依赖训练期扰动、故障数据、奖励、价值函数或验证器，难以直接用于无任务反馈的执行偏移。
  • 本文研究 MuJoCo/robosuite 仿真中的闭环操作：冻结 VLA 权重，VLA 输出动作块，外部控制器在执行时根据机器人状态持续重规划；视觉观测和任务保持不变，只改变动作到物理运动的映射。
  • 作者目标是：不使用奖励、任务演示或梯度更新，仅靠任务无关的电机探索数据，在检测到执行偏移后恢复冻结 VLA 的预期轨迹，同时避免适配器在无偏移时破坏原策略。

Latency 400\,ms (paired episode).
  • 整体流程为：冻结 VLA 生成动作块 → 名义机体模型 \(f_{\mathrm{nom}}\) 将动作块展开为“预期运动轨迹” → 部署机体模型 \(f_{\mathrm{dep}}\) 预测新执行动力学 → 信赖域 MPC 求出能跟踪预期轨迹的新动作 → CUSUM 残差监控器决定何时启用修正。
  • 意图读出：作者不借助任务奖励，而是把 VLA 的动作块输入在名义机体探索数据上拟合的前向模型；所得状态路径被视为策略在训练机体上原本想实现的运动。
  • 部署机体辨识：在限定工作空间内执行平滑的 Ornstein–Uhlenbeck 电机探索，也可混入 VLA 驱动的转移；由任务无关的状态—动作—下一状态数据训练前向模型集成，并估计动作延迟 \(\hat d\) 和线性动作映射 \(M\)。
  • 重落地控制：循环时域控制器在部署模型中最小化两项代价——对名义预期轨迹的跟踪误差，以及修正动作偏离 VLA 重定时、重映射后动作锚点的二次惩罚。它改变的是执行动作，不改变 VLA 的视觉语言推理或参数。
  • 求解与执行：使用批量 CEM 优化短时域动作序列，每次仅执行首个修正动作，并沿用 VLA 给出的夹爪命令，下一控制步重新求解，形成闭环修正。
  • 安全启用：单侧 CUSUM 累积名义模型的一步归一化残差；报警前原样执行 VLA，报警后才启用 ReGround。该设计使适配器在未检测到偏移时保持恒等映射，而不是始终干预策略。

实验与结果

  • 在 \(\pi_{0.5}\) 的 400 ms 延迟测试中，Base 成功率仅为 0.16，ReGround 提升至 0.90，接近解析逆模型 Oracle 的 0.91；相对最佳非 ReGround 基线高 0.74，危险 episode 率也由 Base 的 0.86 降至 0.35。
  • 对 \(\pi_{0.5}\) 的五个测试单元，ReGround 成功率为 0.90–0.98，作者称恢复了 0.91–1.00 的损失成功率。250 ms 延迟下成功率为 0.96，高于 Intent 的 0.80；复合偏移下为 0.97，高于 Linear 的 0.86、Intent 的 0.67及 Oracle 的 0.92。
  • 对静态动作重映射，Linear 已能恢复成功率，但安全性较差：90° 旋转下 Linear 与 ReGround 均为 0.98 成功率，危险率分别为 0.76 和 0.29；增益乘 3 下二者成功率分别为 0.94 和 0.96，危险率分别为 1.00 和 0.77。Intent 在若干单元更安全，但通常伴随较低成功率。
  • ReGround 未针对 SmolVLA 重新调参，仍在 250 ms 延迟下把成功率从 0.19 提至 0.93，在复合偏移下从 0.00 提至 0.78；对应危险率分别由 0.54 降至 0.05、由 0.29 降至 0.10。其在静态旋转和增益偏移上的成功率则略低于部分基线。
  • 数据效率与监控方面，250 ms 延迟下仅 1,000 条探索转移、约 50 秒机器人时间即可达到 0.98 成功率，而 Intent 需要 10,000 条；监控器捕获了所有偏移 episode，对无偏移 episode 的误报率为 2.1%。无偏移测试中，ReGround 的成功率为 0.98，对应冻结 VLA 为 0.97，危险率约为 0.40–0.41。

局限与可以继续做的

  • 证据仅来自 MuJoCo/robosuite 中八个 LIBERO 任务，原文没有真机实验；仿真中的延迟、坐标旋转和增益变化不能覆盖真实机器人上的摩擦、回程间隙、柔性、温漂、传感器失准及非平稳磨损。
  • 方法依赖名义与部署机体前向模型的预测质量，并假定 VLA 在名义机体上的动作仍能表达正确任务意图。若失败源于视觉误识别、语言理解错误或策略本身选错目标，ReGround 可能忠实跟踪一条错误轨迹，无法从根本上纠正。
  • 危险率虽通常优于 Linear，但并未被消除，例如 \(\pi_{0.5}\) 增益乘 3 时 ReGround 的危险 episode 率仍为 0.77；本文采用经验性安全事件定义和残差报警，而非带可证明约束的安全控制器。
  • 可继续做真机渐进式测试：先在空工作空间采集短时电机探索数据，再加入载荷变化、关节老化和时变延迟；同时分别报告检测延迟、误报、修正期间碰撞率和恢复后的任务成功率，而不只汇总 episode 均值。
  • 可把 MPC 接入控制屏障函数、速度/力矩硬约束或碰撞预测器，并测试模型不确定性触发的降速、停止与重新探索机制；还应比较“一次离线探索”与“在线持续更新部署模型”在非平稳偏移下的稳定性。
实验设置
  • 仿真平台：MuJoCo、robosuite，控制频率 20 Hz。
  • 任务：八个 LIBERO 操作任务。
  • 策略：冻结的 \(\pi_{0.5}\) 与 SmolVLA；SmolVLA 实验未重新调参。原文节选未披露具体检查点名称或是否通过 OpenPI 加载。
  • 动作接口：每个动作包含 6 维末端执行器增量和夹爪命令；VLA 一次输出 \(T=50\) 步动作块，先执行其中 \(n=10\) 步再查询策略。
  • 机器人状态：末端执行器六维旋转表示、夹爪状态、关节位置和速度，共 25 维；学习到的机体模型不包含任务或物体状态。
  • 偏移类型：动作坐标系旋转、控制器增益变化、命令延迟以及复合偏移，共四类、五个 \(\pi_{0.5}\) 测试单元；具体测试包括 250/400 ms 延迟、90° 旋转、增益乘 3和复合偏移。SmolVLA 表中使用 250 ms 延迟、30° 旋转、增益乘 2及复合偏移。
  • 对照：Base、Linear、一步逆动力学迁移 Intent、解析逆模型 Oracle；SmolVLA 表中未报告 Oracle。
  • 数据划分：验证状态编号 0–14，测试状态编号 15–49；超参数只在验证状态上选择。
  • 重复与配对：使用 3–5 个适配随机种子，并对不同方法配对 VLA 噪声。
  • 指标：八个任务与随机种子上的分层均值四分位数 IQM，并使用分层 bootstrap 区间；节选正文未给出区间的具体数值。
  • 危险 episode 定义：发生非目标接触、物体移位或掉落，或违反速度包络。
  • 控制器：批量 CEM 求解循环时域优化；实验中 \(H=1\) 的成功率与更长时域相当。原文节选未披露 CEM 样本数、迭代数、\(\lambda\)、折扣因子、CUSUM 阈值及前向模型网络结构的具体取值。
AI导读和推荐理由
  • 这篇论文切中 π 系列部署中容易被忽略的接口问题：高层视觉语言策略可能判断正确，但训练时动作语义与部署机器人实际响应不一致，仍会导致任务失败和危险运动。
  • 它提供了一条不修改大模型权重的工程路径：把“模型适配”转化为动作接口层的意图读出、动力学辨识、闭环重落地和异常监控，适合权重不可访问或不希望重新训练 VLA 的场景。

与π系列的关系

  • 本文直接评测了冻结的 \(\pi_{0.5}\)，核心结论是 \(\pi_{0.5}\) 在目标识别和任务意图仍正确时，也会因执行映射变化而崩溃；400 ms 延迟使其测试成功率从正常能力水平降至 0.16，而外挂 ReGround 后恢复至 0.90。
  • ReGround 不修改 \(\pi_{0.5}\) 的网络结构、训练目标或权重，也不使用 π 系列内部的 value、reward 或 verifier；它位于 VLA 动作输出与机器人控制器之间，用名义机体模型解释动作意图，再用部署机体模型重新生成执行动作。
  • 论文没有评测 \(\pi_0\)、\(\pi_0\)-FAST，也未说明 \(\pi_{0.5}\) 是否来自 OpenPI 的哪个检查点；因此不能把结果直接外推到不同动作 tokenizer、不同 chunking 方式或不同 OpenPI 机器人适配器。
  • 与重新微调 π 模型相比，ReGround 的优势是无需任务演示、奖励和梯度；代价是需要名义机体模型、部署前电机探索以及在线 MPC，其适用前提是基础策略的任务意图本身仍然可靠。

对Austin研究的启发

  • 可在 OpenPI 执行器接口中明确拆分三层：原始 VLA action chunk、经过延迟/坐标映射后的 action anchor、最终由闭环控制器输出的实际命令；日志同时保存三者，便于判断失败来自语义策略还是执行落地。
  • 建议为 π 系列评测加入“固定观测、仅改变执行器”的压力测试矩阵：动作坐标旋转、增益缩放、固定与随机延迟、复合偏移，并同时报告成功率、危险 episode 率和恢复时间，而不只测试视觉域偏移。
  • 若已有引导场 \(G\) 或轨迹条件，可把 ReGround 的名义轨迹作为 \(G\) 的执行参考，检查部署后的真实状态是否持续遵循该条件；一旦轨迹残差和模型不确定性同时升高，则降速、停止或切换到重落地控制。
  • 可先复现最有辨识度的协议：冻结 OpenPI 中的 \(\pi_{0.5}\)，注入 250/400 ms 动作延迟，分别比较原策略、静态线性校准、一步逆动力学和闭环 ReGround；随后做 1,000、5,000、10,000 条探索数据的样本效率曲线。
  • 真机接口还应加入动作限幅、碰撞/力矩约束和监控器迟滞，避免 CUSUM 在噪声边界附近频繁开关；同时独立记录检测延迟与检测前发生的危险动作，因为“最终检测到”并不等价于及时安全干预。

一句话总结

  • UTSA 的 Siddique、Li 与 Cao 提出 ReGround，以任务无关电机探索学习部署动力学并在冻结 VLA 外进行受信赖域约束的闭环轨迹重落地，将 \(\pi_{0.5}\) 在 400 ms 延迟下的成功率从 0.16 恢复到 0.90。
