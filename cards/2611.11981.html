深读｜Thermo-VLA

📐 原版模型结构图详解🤖 向千问提问本篇论文原文 ↗

问题

  • 现有 VLA 主要依赖 RGB；当指令涉及温度等不可见物理属性时，策略无法仅凭外观可靠完成目标选择、相对温度比较或排除式推理。
  • 已有热感知操作方法通常把热图直接当作普通图像或伪彩色视觉输入，容易让显著热源压过任务真正需要的温度关系，并可能引发选错目标、双臂同时动作、单侧动作偏置或抓取不稳定。
  • 既有工作多集中于固定视角、单臂和简单的“识别并抓取冷热目标”；本文转向 Unitree G1 双臂真机上的第一视角操作，覆盖 RGB 定位、温度感知、相对排序和热排除推理。
  • 作者目标是在保留 π0.5 连续动作生成能力的同时，以任务语言选择性地注入温度属性，使策略兼顾 RGB 操作能力、复杂热推理和场景泛化。论文未说明是否冻结 π0.5 权重，也未明确动作块执行期间的重规划频率，因此不能据此判定为严格开环或逐步闭环控制。

方法

  • 整体流程为：头部及腕部 RGB 图像、头部热图、语言指令和机器人状态输入编码器；ThermoRes Encoder提取并注入温度属性；Gemma 多模态骨干与 action expert 基于增强后的前缀，通过 π0.5 原有流匹配机制生成双臂连续动作块。
  • 双分支温度属性分解：从图像上边界附近采样多个 patch，以其平均强度的众数估计每帧背景温度参考，将背景校准到固定灰度，再分别构造突出低于背景和高于背景响应的 cold、hot 视图，降低绝对热强度随场景变化造成的歧义。
  • cold 与 hot 分支共享 SigLIP 热编码器，并复用 RGB projector，使温度 token 与 RGB token 具有相同布局和维度，可直接进行逐 token 调制，而不是把热图作为一个未经结构化处理的额外视觉输入。
  • 文本门控交叉注意力以文本 token 为 query，分别读取 cold/hot token；Gate MLP结合池化文本、两路注意力输出及其与文本表示之差，经 softmax 得到动态权重 \(\alpha,\beta\)，按当前指令调整冷热属性贡献。
  • 残差注入保留头部 RGB token 作为 identity path，分别形成 \(Z_{\mathrm{rgb}}^{\mathrm{head}}+\alpha Z_{\mathrm{cold}}\) 与 \(Z_{\mathrm{rgb}}^{\mathrm{head}}+\beta Z_{\mathrm{hot}}\)。这样不替换 RGB 的外观和空间语义，而是加入与指令相关的温度修正。
  • 本文改动重点是 π0.5 的多模态感知编码；Gemma-based 多模态骨干、action expert 以及从高斯噪声演化出连续动作块的 flow-matching 生成方式被保留。原文未说明哪些基础权重被冻结或全部参与微调。

实验与结果

  • 在四项温度相关真机任务 II、IV、V、VI 上，Thermo-VLA 的成功率分别为 1.00、0.86、0.58 和 1.00，平均为 0.86；直接把热图作为额外视觉观测的 π0.5（RGBT）分别为 0.80、0.85、0.50 和 0.55，平均约 0.68。论文将总体提升概括为 18 个百分点。
  • 优势主要出现在需要推理而非仅识别热目标的任务：相对温度咖啡服务任务中，Thermo-VLA 为 0.58，π0.5（RGBT）为 0.50，ThermoAct 为 0；热排除任务中，Thermo-VLA 为 1.00，π0.5（RGBT）为 0.55，ThermoAct 为 0.50。
  • 在较简单的温度感知与热 grounding 任务上，Thermo-VLA 相对 π0.5（RGBT）的优势较小：Task II 为 1.00 对 0.80，Task IV 为 0.86 对 0.85，说明主要增益并非均匀分布，而是在条件选择和排除式推理中更突出。
  • Thermo-VLA 没有完全保持原始 π0.5 的 RGB-only 水平：Task I 平均成功率为 0.88，对比 π0.5 的 0.93；Task III 为 0.76，对比 0.84。不过它在两项任务上均优于 π0.5（RGBT）的 0.85 和 0.71，也显著高于 ThermoAct 的 0.45 和 0.49，表明结构化残差注入减轻了额外热模态对 RGB 操作的干扰。
  • 典型失败中，ThermoAct 出现单侧动作偏置和抓取不稳定，π0.5（RGBT）会同时操作两个物体，或在排除任务中误选最显著的热目标；Thermo-VLA 的注意力则集中到没有热响应的目标。摘要另报告未见物体与场景变化下平均成功率为 0.78，但所给正文未包含各变化条件的分项数字。
  • 作者还把相同残差调制机制迁移到颜色属性，并称仿真与真机均获得一致改进；当前提供的正文片段没有给出对应任务、基线或具体数值，不能进一步量化。

局限与可以继续做的

  • 证据主要来自单一 Unitree G1 双臂平台和六项自建任务，其中温度相关任务只有四项；尚不能证明该机制可直接迁移到其他机器人形态、热相机、环境温区或更长时程任务。
  • 每条指令评测 20 次，表格仅报告成功率，未提供置信区间、跨随机种子结果、动作平滑性、碰撞率、推理延迟或温度校准误差，尤其需要谨慎解释 0.05–0.10 量级的差异。
  • 背景参考来自图像上边界 patch 的统计众数，隐含该区域能代表背景的假设；当上边界被热源、人体、反射面或机器人自身热量占据时，冷热分解可能失准。可直接加入遮挡、背景温漂和多热源干扰测试，并比较固定参考、在线鲁棒估计与原始辐射温度输入。
  • RGB-only 任务仍比原始 π0.5 低 5 和 8 个百分点。可增加“无需热信息”门控或零残差旁路，并记录 \(\alpha,\beta\) 的分布，检验语言是否能在纯 RGB 指令下真正关闭热模态。
  • 可在 OpenPI/π0.5 执行接口中复现 ThermoRes：固定相同数据、action horizon 与训练预算，对比直接拼接、伪彩色输入、单分支残差和双分支文本门控；同时加入未见温度区间、相机错位、热延迟和跨 embodiment 评测，以区分表示增益与数据或平台特化。
实验设置
  • 平台：Unitree G1 双臂人形机器人。
  • 传感器：刚性安装且保持固定相对位姿的头部 RGB 相机与热相机，以及左右腕部 RGB 相机。
  • 动作空间：预测长度为 \(H\) 的连续双臂动作块，形状为 \(H\times2d_a\)；\(d_a=8\)，每臂包括 7 个关节维度和 1 个手部开合维度。
  • 基础模型：π0.5；使用 Gemma-based 多模态骨干、action expert 和 flow-matching 连续动作生成。具体检查点、冻结范围和训练硬件在所给正文中未披露。
  • 数据总量：1,307 条专家示范。
  • Task I“位置引导瓶子选择”：156 条，Spatial Grounding。
  • Task II“温度引导瓶子选择”：303 条，Thermal Perception。
  • Task III“身份引导物体选择”：236 条，Appearance Grounding。
  • Task IV“温度引导物体选择”：340 条，Thermal Grounding。
  • Task V“温度感知咖啡服务”：173 条，Thermal Ranking。
  • Task VI“异常动物笼移除”：99 条，Thermal Exclusion。
  • 对比方法：RGB-only 的 ACT、π0.5，以及 RGB–thermal 的 π0.5（RGBT）、ThermoAct 和 Thermo-VLA；π0.5（RGBT）把热图直接作为额外视觉观测，各基线采用其原论文超参数。
  • 评测协议：每条指令执行 20 次；Tasks I–IV 要求将正确目标放到正确杯垫，Task V 要求向指定温度状态的咖啡倒糖，Task VI 要求将无热响应小鼠所在笼子移到危险标记箱。
  • 每轮后由佩戴隔热手套的操作员复位；同一 trial 在不同方法间尽量匹配物体位置，不同 trial 改变布局；同一测试组内液体重量保持一致。
  • 热图预处理涉及背景参考 \(b\)、固定背景灰度 \(\mu\) 和灰度上界 \(I_{\max}\)，但所给正文未披露 \(\mu\)、采样 patch 数量、action horizon、训练步数、学习率或推理频率的具体取值。
AI导读和推荐理由
  • 推荐这篇的核心原因不是“给 π0.5 多接一台热相机”，而是它明确展示了直接增加模态可能破坏 RGB 操作，并提出了属性分解、语言选择和残差注入三者结合的接口。
  • 四项温度任务平均 0.86、较直接 RGBT 输入高约 18 个百分点，且最大差距出现在热排除推理，说明多模态 VLA 的关键问题不仅是能否感知新信号，还包括如何让信号服从语言条件并避免显著性捷径。

与π系列的关系

  • Thermo-VLA 直接以 π0.5 为基础策略和主要基线，保留其 Gemma-based 多模态条件建模、action expert 与 flow-matching 连续动作生成，主要改造位于 RGB/thermal token 进入动作模型前的感知融合层。
  • 它不是 π 系列官方新模型，也没有提出新的动作 tokenizer、动作专家或流匹配目标；其贡献更接近可接入 π0.5 的热属性编码与调制模块。
  • ThermoAct 采用 Gemini 2.0 Flash planner 和 π0 executor，是本文对比方法之一；它将热图转换为伪彩色后交给通用视觉编码器，与 Thermo-VLA 的显式冷热属性分解不同。
  • 所给正文没有报告 π0、π0-FAST 或 OpenPI 上的等价实现，也未证明与 OpenPI 存在代码或训练框架层面的继承关系；不能把本文结果直接视作这些变体上的验证。

对Austin研究的启发

  • 可把 ThermoRes 做成 OpenPI 执行器前的标准化 modality adapter：输出与 RGB token 同形状的属性残差，并保持 policy/action expert 接口不变，从而低成本比较热觉、深度、触觉或颜色属性。
  • 在引导场 \(G\) 或语言条件遵循研究中，可显式监控 cold/hot gate 权重、残差范数及目标区域注意力；若纯 RGB 指令仍产生大残差，或“排除热目标”时 gate 只追随最强热源，可作为在线异常信号。
  • 评测应加入“直接拼接新模态导致能力回退”这一维度：除了热任务成功率，还要报告原有 RGB 任务的 retention、错误手臂激活率、双目标误操作率和无关模态关闭能力。
  • 闭环复现时可系统改变 action horizon、重规划频率与热图时间延迟，判断 ThermoRes 的收益来自目标选择还是轨迹稳定；原文未披露这些因素，正适合作为补充实验。
  • 数据设计上应加入同一物体跨冷热状态、冷热属性重组、背景温漂、无关强热源和否定式指令，使模型不能靠物体身份或最高热强度完成任务。

一句话总结

Thermo-VLA在 π0.5 感知端加入语言门控的冷热双分支残差调制，在 Unitree G1 四项温度任务上取得 0.86 平均成功率、较直接 RGBT 输入高约 18 个百分点，但所给论文正文未披露作者机构及 OpenPI/π0-FAST 验证。
