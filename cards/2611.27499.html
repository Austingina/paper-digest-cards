NavRSI: Recursive Harness Self-Improvement for Vision-and-Language Navigation

📐 原版模型结构图详解🤖 向 AI 提问本篇论文原文 ↗

问题

  • 前沿多模态 LLM 已能通过视觉观测和工具调用直接闭环导航，但性能高度依赖连接模型与环境的 harness；同一冻结模型仅因 harness 不同，就可能出现明显的成功率差距。
  • 现有 harness-based VLN 通常由人工预设深度查询、目标定位、航点执行、结构化记忆或多智能体角色，难以根据真实闭环轨迹中反复碰撞、航向丢失、路径回访、过早停止等失败自动调整。
  • 导航失败来自长时序、部分可观测的感知—推理—动作耦合，单一成功率无法指出应如何修改 harness；与此同时，仿真器中的目标距离、阻塞动作等特权诊断在真机部署时不可用。
  • 本文研究连续环境中的闭环 VLN：冻结导航 LLM，只使用单目 RGB 与前进、转向、停止等原始动作，通过训练场景中的闭环经验优化外围 harness，而非训练策略权重或增加导航专用工具。
  • 作者的目标是自动发现可部署、跨模型和跨场景泛化的轻量 harness，在提高成功率的同时控制 token、API 成本与运行开销。

方法

  • 任务输入与执行接口（Problem Setup）：给定语言指令 $I$ 和环境 $e$，冻结的导航器 LLM $\mathcal{M}$ 由程序外壳（harness）$h_k$ 驱动；其仅调用 observe 获取前向 RGB 图像，并用 step 输出前进、转向或 STOP 等原子动作，形成闭环轨迹 $\tau=h_k(I,e;\mathcal{M})$。
  • 单轮递归自改进（One RSI Round）：在第 $k$ 轮中，$\mathcal{M}$ 固定不更新，并在训练集执行多个 episode；Designer 读取轨迹中的 closed-loop logs 与累积经验 $E_k$，据此重写导航上下文、工具及反馈逻辑，输出下一轮外壳 $h_{k+1}$，同时提炼并更新经验 $E_{k+1}$。
  • 信息隔离与联合演化（Isolation Wall）：隔离墙严格拆分同一步的信息：Navigator 可见相机视图、不可见 simulator diagnostics；Designer 可见诊断信息、不可见原始图像。由此避免诊断信号直接泄漏给导航器，同时使 harness rewriting 与 experience accumulation 随轮次协同演化。
  • 搜索曲线与最终外壳（Search-set SR / Final Harness）：每轮候选外壳仅通过训练 episode 搜索，并保留 search-set 成功率（SR）最高者；图(b)同步展示最佳 SR 与经验库 $E_k$ 的增长。递归结束后固定最终 $h^*$ 用于评测，对应目标 $\arg\max_h\mathbb{E}_{(I,e)\sim\mathcal D_{\mathrm{unseen}}}[s(\tau)]$。

Overview of NavRSI. (a)~One RSI round: in harness $h_k$, the frozen navigator runs training episodes, and the designer reads the closed-loop logs and its experience $E_k$ to write $h_{k+1}$ and $E_{k+1}$. An isolation wall splits what the two see at the same step: the navigator gets the camera view but no simulator diagnostics, and the designer gets the diagnostics but no image. (b)~Search-set SR of each round's best harness, and the growing experience. (c)~The final harness for evaluation.
  • 整体流程为“导航 rollout → 失败诊断 → designer 重写 harness → 分阶段筛选 → 经验累积”：冻结 navigator 在当前 harness 下执行训练 episode，designer 根据完整执行日志和仿真诊断生成候选代码，评估后保留截至当前搜索集成功率最高的版本。
  • NavRSI 从通用 Mini-swe-agent harness 出发，只允许改写提示词、agent loop、反馈内容及反馈时机；navigator、observe/step 工具和动作预算均保持不变，也不增加深度、航点、地图或学习策略等导航工具。
  • Designer 每轮在新会话中运行，同时维护四部分优化经验：失败统计、每次修改背后的假设、对运行随机性的效果核验，以及下一轮应尝试或避免的方向。该经验与 harness 共同迭代，避免只保存候选代码和分数而丢失“为什么有效”。
  • 候选 harness 先通过规则检查与 dry run，再在搜索集上分阶段评测；明显落后于历史最佳者会被提前终止，最终版本另用 development episodes 选择。
  • 方法实施严格的信息隔离：navigator 只能看到指令、RGB 图像与可在真机获得的动作反馈；designer 看不到图像，但能读取训练 rollout 的日志、目标距离、参考路径进度、阻塞动作和失败类型。特权信息只用于设计 harness，不进入部署接口。
  • RSI 最终自动形成六个模块、三类能力：通过连续图像变化检测疑似受阻并检查地面；用起始环视、隐式航向/俯仰标签及相似视图匹配追踪进度和回访；把第一次 STOP 改为提议，再通过到达环视和更高推理等级的审查执行至多两次纠正。所有平移动作仍由 navigator 决定，harness 只会原地转动或俯仰相机来补充观测。

实验与结果

  • 在完整 R2R-CE val-unseen 上，GPT-6-Astra + NavRSI 达到 85.64% SR、73.58% SPL、2.11 NE、89.45% OSR。论文列出的 NavGPT-3 外部结果为 81.51% SR、70.42% SPL，因此 NavRSI 的 SR 高 4.13 个百分点，且不使用 NavGPT-3 所依赖的额外训练 8B VLA。
  • 在 R2R-CE-100 上，同一最终 harness 直接替换模型即可用于四个厂商的 LLM，相对各模型原生 harness 的 SR 最高提高 11.3 个百分点。正文给出的 GPT-5.6-Sol 示例中，Codex CLI、Mini-swe-agent 和 NavRSI 的 SR 分别为 56.7%、58.7% 和 68.0%。
  • R2R-CE 上得到的 harness 未经 RxR-CE 调优，直接迁移到完整 RxR-CE val-unseen 后取得 88.96% SR、71.99% SPL、78.97 nDTW、1.78 NE；其 SR 低于表中 NavGPT-3 的 90.43%，但 NE 和 nDTW 更优。另一个针对同一 800 个 episode 的效率协议中，NavRSI 为 89.25% SR、73.30% SPL，两组数字来自不同表格与评测协议，不宜混用。
  • 在 NavRAG-CE 的 100 个 val-unseen episode、三次运行协议下，NavRSI 跨数据集迁移取得 39.7±5.0% SR、27.4±1.3% SPL、66.7±1.5% OSR、7.00±0.26 NE；同协议 MIP 为 34.3±3.8% SR、21.3±1.1% SPL。
  • RxR-CE 的 800-episode 效率对比中，NavRSI 每 episode 使用 255.1k tokens、0.424 美元、312.8 秒、0.93 GB GPU 显存；Codex CLI/MIP 分别为 706.8k tokens、1.086 美元、434.8 秒和 0.93 GB。相较 Codex CLI，论文概括其平均 tool calls、token 和 API 成本分别减少 5%、61% 和 68%。
  • 消融证据显示闭环 RSI 不是一次性提示词生成：由同一 designer 一次写出的 harness 均低于初始 Seed 0。若不保留此前轮次记录，52.8% 的新修改会重复已有方案；只保留累积经验 \(E_k\) 时，论文报告重复率为 0。所给原文未包含完整消融表，无法核对各模块对应的绝对 SR 降幅。
  • 论文还报告在 Unitree G1 人形机器人上的真机泛化，但所给原文没有披露真机任务数、成功率、场景构成或误差指标，因此不能据此量化 sim-to-real 效果。

局限与可以继续做的

  • NavRSI 没有训练导航模型，却仍依赖多轮仿真 rollout、特权诊断和 frontier designer LLM；这些成本被移到部署前的 harness 搜索阶段。原文片段未给出总搜索 episode 数、候选总量、designer token 成本或完整计算预算，尚不能判断搜索成本是否优于训练或人工工程。
  • 搜索集来自 R2R-CE training scenes，最终 harness 又针对 development episodes 选择。虽然作者设置了信息隔离与防止嵌入 episode 内容的规则，但仍需在更多建筑分布、语言风格和机器人形态上检验其是否学习到通用交互规律，而不是 R2R-CE 特有的失败模式。
  • 特权诊断不会泄漏给 navigator，但搜索阶段默认仿真器能够提供目标距离、参考路径进度和失败类型。可进一步做“诊断带宽消融”：依次移除参考路径、目标距离和人工归类的失败标签，测量 SR/SPL 与搜索轮数的变化，以确定真实数据采集条件下最低所需监督。
  • 最终 harness 依赖连续 RGB 相似度判断阻塞和回访，并以执行动作推断航向，没有显式几何状态或真实里程计；光照变化、动态物体、视觉混淆和动作滑移都可能破坏这些启发式信号。可加入仅用于 harness 的不确定度监控，并在保持单目部署条件的前提下，对比视觉里程计或轻量拓扑记忆。
  • 到达审查会主动环视、提高一次推理等级并允许至多两次纠正，成功率提升可能伴随额外动作和延迟。应分别报告导航动作、原地观测动作、审查触发率及错误回退率，分析 SR 与 SPL、实时性之间的权衡。
  • 真机证据在所给原文中不足。可在 Unitree G1 上按障碍类型、指令长度、跨楼层或跨房间类别建立重复试验，并报告 SR、SPL/路径效率、碰撞率、急停次数和端到端延迟，而不仅展示成功案例。
实验设置
  • 主要仿真任务：R2R-CE、RxR-CE 和 NavRAG-CE；主评测使用连续环境中的 val-unseen split。
  • 搜索数据：仅使用 R2R-CE training scenes 中的 episode；designer 不访问 development 或 test episode，最终 harness 通过 development episodes 选择。
  • 完整 R2R-CE 和 RxR-CE 的表格报告 NE、OSR、SR、SPL；RxR-CE 另报告 nDTW。
  • R2R-CE-100：100 个 episode；各 LLM 使用默认 API reasoning effort，NavRSI 的 arrival audit 比默认提高一个 reasoning-effort level；导航指标为三次运行的均值与标准差。
  • NavRAG-CE：100 个 val-unseen episode，使用 GPT-6-Astra，运行三次并报告均值±标准差；NavRSI 直接使用从 R2R-CE 得到的 harness，不在 NavRAG-CE 上调优。
  • RxR-CE 效率实验：同一组 800 个 val-unseen episode，navigator 为 GPT-6-Astra；时间与显存均在 RTX 5000 上测量。
  • 真机平台：Unitree G1 人形机器人；部署时只使用单个 RGB 相机与原始动作。所给原文未披露相机参数、控制频率、真机 episode 数及场景数量。
  • Navigator：冻结的通用 LLM；最终实验覆盖四个厂商的 LLM。完整模型列表和各自检查点在所给原文中未完整显示。
  • Designer：每轮开启新会话的 frontier LLM；搜索 rollout 使用低成本替代模型 \(\mathcal{M}_{\ell}\)。原文片段未给出这两者的具体检查点。
  • 初始 harness：开源 Mini-swe-agent Seed 0；最终 harness 在不同 LLM 间保持完全相同，只更换 navigator。
  • Navigator 工具仅有两个：observe 返回当前单目 RGB 视图，step 执行一组原始动作。
  • 原始动作示例：前进 0.25 m、左转或右转 15°、STOP。
  • RSI 每轮生成 \(C\) 个候选，先规则检查和 dry run，再分阶段评测；所给原文未给出 \(C\)、总轮数、搜索集大小及提前终止阈值的具体数值。
  • 仿真诊断包括每次 step 后的目标距离、沿参考路径的进度、受阻动作，以及 stuck、early stop、near miss 等 episode 级失败类型。
  • 信息隔离：navigator 不接收任何仿真诊断；designer 读取的日志中，所有图像均替换为占位符。每个 episode 在新进程中执行，并以规则检查防止候选代码嵌入 episode 内容。
  • 最终 harness 不增加深度、位姿、全景图、航点执行器、结构化记忆或额外 agent role；仅在单个 episode 内保存历史视图用于相似度比较。
AI导读和推荐理由
  • 推荐这篇的核心原因不是又提出一个导航模型，而是把 VLN 的优化对象从策略权重转向可执行 harness：模型保持冻结，失败轨迹被转化为反馈、观测调度和停止校验机制。
  • 它同时给出了有价值的工程边界：优化阶段允许使用仿真特权信息，部署阶段则严格退化为单目 RGB 和原始动作接口；这比直接把深度、真值位姿或目标距离交给 navigator 更接近 sim-to-real 的信息条件。

与现有VLN/SLAM对比

  • 相对训练型 VLN/VLA，NavRSI 不训练视觉导航策略，也不依赖数百万条额外样本；其主要增量是针对冻结 frontier LLM 自动搜索交互脚手架，而不是提升模型内部的空间表征。
  • 相对 MIP、Codex CLI 或 Mini-swe-agent，工具接口与 navigator 不变，改进来自动作反馈、进度跟踪和到达复核。因而实验更直接地说明：闭环 VLN 的瓶颈不只有基础模型能力，也可能是 harness 如何组织观测与反馈。
  • 相对 NavGPT-3、ASENA 等“LLM + 已训练导航模型”方案，NavRSI 不外挂 VLA 或 waypoint policy；代价是动作效率和稳定性更多依赖大模型推理及视觉启发式检查，未获得学习型低层控制器的几何先验。
  • 相对经典 SLAM/GoalNav，NavRSI 不构建显式度量地图，也不执行全局定位、回环优化或几何路径规划。它以起始环视、动作推断航向、视图相似度回访检测形成弱拓扑/弱几何状态，接口轻、迁移方便，但缺少可度量的一致地图与定位置信度。
  • 特权诊断只训练“如何组织交互”，而不进入导航时的观测。这可视为一种 harness-level privileged learning：部署接口很轻，但搜索过程仍需具有真值状态和参考路径的仿真环境。
  • 与人工设计 prompt 或 workflow 相比，NavRSI 的关键增量是闭环筛选和可更新的 designer 经验；一次性生成的候选均不及 Seed 0，说明“让 LLM 写 harness”本身不足，必须用实际 episode 结果淘汰看似合理但无效的设计。

对Austin启发

  • 在空间几何表示上，可以保留 NavRSI 的轻量部署接口，但将当前“动作积分航向 + 图像相似度”替换为带置信度的局部拓扑图：节点保存关键视图和相对朝向，边保存动作执行结果、阻塞概率与重定位置信度，再比较 SR、SPL 和额外 token。
  • 在分层规划/控制接口上，可明确拆分为语言级子目标、几何级局部目标和安全控制三层；允许 RSI 只改写层间消息、重规划触发器和停止条件，不允许修改底层安全约束。这样能检验 harness 优化是否可迁移到 π/OpenPI 类策略或传统局部规划器。
  • 对失败诊断建立统一事件协议，例如 blocked、loop_detected、heading_uncertain、goal_ambiguous 和 stop_rejected。仿真中由真值生成标签，真机中由视觉里程计、碰撞检测和策略不确定度近似生成，再测量诊断域差异对迁移的影响。
  • 为跨场景泛化增加“留一环境族”实验：分别在住宅、办公、长走廊和开放区域上搜索 harness，再交叉测试，统计哪些模块稳定保留、哪些模块过拟合场景结构。
  • 把 harness 搜索纳入多目标评价，而不是只以搜索集 SR 选优：至少同时约束 SPL、碰撞/阻塞次数、token、API 成本、动作数和到达误判率，避免通过过度环视或反复审查换取成功率。
  • 对真机应优先复现实验中的信息隔离，而不是照搬仿真诊断：设计智能体可以离线读取标注后的真机日志，但在线 navigator 仍只接收机器人实际可获得的 RGB 与动作反馈，以验证改进是否真正来自可部署机制。

一句话总结

NavRSI 由新加坡管理大学等机构作者提出，通过闭环轨迹驱动的递归 harness 重写提升冻结 LLM 的连续 VLN 能力，在完整 R2R-CE val-unseen 上以 GPT-6-Astra 达到 85.64% SR、73.58% SPL 和 2.11 NE，但其搜索成本及 Unitree G1 真机成功率在所给原文中尚未完整披露。
